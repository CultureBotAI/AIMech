Stack-augmented recurrent neural network

Architectures AIMech:StackAugmentedRecurrentNeuralNetwork DRAFT
Aliases: Stack RNN
A recurrent sequence architecture whose neural controller reads the leading entries of one or more external stack states and learns continuous mixtures of push, pop and optional no-operation updates to those states.

Claims & Grounded Evidence

6 Claims
Mechanism #controller-and-stack-transition
The controller forms h_t from the current input, optional previous hidden state and the top k entries of the previous stack. It computes softmax action weights and a sigmoid-valued push proposal v_t. For push weight p and pop weight q, the new top is p*v_t+q*s_prev[1]; a deeper entry i>0 becomes p*s_prev[i-1]+q*s_prev[i+1]. An optional no-op weight n adds n*s_prev[i] at each depth. The paper and pinned code use -1 as the empty-slot sentinel. Read depth, number of stacks and boundary capacity are configuration choices.

Scope #continuous-versus-discrete-state
Soft action weights deterministically blend candidate memory updates rather than sample one discrete stack action. One-hot weights recover the corresponding push, pop or no-op operation when the chosen capacity and sentinel boundaries permit it. At nontrivial mixtures the state need not represent one symbolic stack. Although a single affine update is a weighted mean of candidate results, subsequent nonlinear controller evolution is not generally the exact expectation over discrete stack trajectories.
  • supports Source: Inferring Algorithmic Patterns with Stack-Augmented Recurrent Nets · Locator: Section4.2 p.4 and optimization/rounding p.5; curator affine-versus-nonlinear consequence
  • supports Source: Author Stack-RNN implementation: StackRNN.h · Locator: StackRNN.h forward136–252
Limitation #capacity-paper-and-code
The paper describes stack depth that can grow on demand as an architectural possibility. The inspected historical StackRNN.h instead allocates a fixed stack_capacity. Its push shifts within that allocation and drops the bottom entry when full; a pop inserts the empty sentinel at the bottom. A push followed by a pop therefore need not restore a previously full stack. Neither the conceptual growing memory nor this finite implementation supplies infinite physical storage, exact arithmetic or unlimited generalization.
  • supports Source: Inferring Algorithmic Patterns with Stack-Augmented Recurrent Nets · Locator: Section4.2 depth/capacity paragraph, p.4; discussion/conclusion p.8
  • supports Source: Author Stack-RNN implementation: StackRNN.h · Locator: StackRNN.h constructor41–84, push217–231 and pop233–238
Scope #hard-actions-versus-rounding
The pinned forward function has an ishard option that replaces softmax weights by one maximal action, choosing the first action index on a tie. The paper separately describes gradual controller-weight sharpening with further weight refinement and removal of unused stacks. Those procedures are not interchangeable: in ideal real arithmetic, finite sharpening remains soft, and equal maximal logits do not approach a unique one-hot decision solely through scaling. Floating-point exponentiation and rounding can nevertheless produce zero/one weights at finite logit gaps; a constructed Python binary64 example demonstrates that possibility without executing the author code. The record does not claim that every inspected code path implements the complete paper refinement/pruning procedure.

Scope #multiple-stacks-and-recurrence
Multiple stacks receive their action decisions through a shared hidden controller and can interact through that hidden representation. Stack push/pop topology is distinct from the paper List RNN with insert and directional movement operations. The general model allows a recurrent hidden-state matrix; the algorithmic toy experiments set it to zero to isolate memory behavior, whereas the language-model experiment uses it. Pinned code exposes separate recurrence modes, so a missing hidden-to-hidden connection is not a universal architecture requirement.
  • supports Source: Inferring Algorithmic Patterns with Stack-Augmented Recurrent Nets · Locator: Section4.2 multiple stacks p.4; List RNN p.5; Sections5.1–5.2 pp.6–8
  • supports Source: Author Stack-RNN implementation: StackRNN.h · Locator: StackRNN.h modes64 and166–180
Limitation #optimization-and-evaluation-boundaries
Continuous updates allow the stated gradient-based training, but the source reports difficult controller optimization, restarts and numerical imprecision on long sequences. Counting and memorization evaluation focuses on deterministically predictable symbols; binary addition uses supervised output positions and reversed results. Published tests cover selected lengths and configurations, and the language-model comparison does not show universal superiority over LSTM or SCRN. No numerical benchmark, general algorithm-learning guarantee, full backward-code correctness or independent reproduction is asserted.
  • supports Source: Inferring Algorithmic Patterns with Stack-Augmented Recurrent Nets · Locator: Optimization and rounding p.5; Sections5–6, pp.5–8

⚠️ Curated Limitations & Negative Results

  • Continuous action mixtures are deterministic relaxed memory updates, not automatically discrete stack semantics or an exact ensemble of symbolic trajectories.
  • Historical pinned code fixes stack capacity; full pushes can irreversibly discard bottom entries. The paper growing-memory abstraction does not certify this implementation as dynamically unbounded.
  • Hard argmax action selection and gradual sharpening/refinement/pruning are different procedures. Ties, numerical precision and finite sharpening limit ideal discrete-operation interpretations. Strict softmax positivity at finite logits refers to ideal real arithmetic, not a promise of strictly interior floating-point results.
  • Stack count, read depth, no-op availability, sentinel boundaries and hidden recurrence vary by configuration; no single benchmark recipe defines all variants.
  • All nine conference-paper pages and complete pinned README.md, StackRNN.h and Nonlinearity.h were read. Supplement, task drivers and other dependencies were not audited; no source execution, training or empirical replication was performed.
  • Source tasks, sequence lengths, supervision and tuning constrain the reported generalization. No unlimited exact memory, universal LSTM replacement or independently verified performance claim is made.
