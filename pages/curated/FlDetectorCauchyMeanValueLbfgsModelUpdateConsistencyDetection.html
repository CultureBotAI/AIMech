FLDetector Cauchy Mean Value and L-BFGS Model-Update Consistency Detection

Algorithms AIMech:FlDetectorCauchyMeanValueLbfgsModelUpdateConsistencyDetection DRAFT
Aliases: FLDetector, FLDetector Malicious Client Detection via Model-Updates Consistency, FLDetector L-BFGS Hessian-Vector Product Update Consistency Detector
An unsupervised server-side malicious-client detection method for federated learning that predicts each client's current gradient update via the Cauchy mean value theorem g_hat_i^t = g_i^{t-1} + H_hat^t (w_t - w_{t-1}) using a quasi-Newton L-BFGS Hessian-vector product estimated from a sliding window of N global parameter differences Delta W_t and global update differences Delta G_t, computes each client's window-averaged normalized Euclidean prediction residual s_i^t = (1/N) sum_{r=0}^{N-1} d_hat_i^{t-r} where d_i^t = ||g_hat_i^t - g_i^t||_2, and uses Gap-statistic k-means clustering to identify and remove inconsistent malicious clients.
Identity Notes & Concept Scope Introduced by Zhang, Cao, Jia, and Gong (KDD 2022, pp. 2545-2555, DOI:10.1145/3534678.3539231, arXiv:2207.09209). Distinct from single-round Byzantine-robust aggregation rules such as Krum, Trimmed-Mean, Median, and FLTrust (AIMech:FlTrustByzantineRobustFederatedLearningViaTrustBootstrapping), which aggregate updates within each iteration without cross-iteration Cauchy-mean-value Hessian consistency prediction, and from VAE-based anomaly detection (Li et al. 2020), which requires a clean server validation dataset to train a reconstruction autoencoder.

Mechanism #c1-mechanism-cauchy-mean-value-lbfgs-hessian-vector-prediction
At iteration t, FLDetector approximates the integrated Hessian-vector product H_hat^t (w_t - w_{t-1}) in O(N^3 + 6Np) time via L-BFGS (Algorithm 1) over the past N global parameter differences Delta W_t = {Delta w_{t-N}, ..., Delta w_{t-1}} and global update differences Delta G_t = {Delta g_{t-N}, ..., Delta g_{t-1}}, predicts each client's update as g_hat_i^t = g_i^{t-1} + H_hat^t (w_t - w_{t-1}) (Eq. 3), and computes normalized Euclidean residuals d_hat^t = d^t / ||d^t||_1 with d_i^t = ||g_hat_i^t - g_i^t||_2.
  • supports Source: FLDetector: Defending Federated Learning Against Model Poisoning Attacks via Detecting Malicious Clients · Locator: Section 4.1-4.3, Equations (2)-(3), Algorithm 1, and Algorithm 3 Lines 2-8, pp. 3-5
Mechanism #c2-mechanism-windowed-suspicious-score-and-gap-statistic-kmeans
FLDetector averages each client's normalized residual over a window of N iterations to form suspicious scores s_i^t = (1/N) sum_{r=0}^{N-1} d_hat_i^{t-r}, applies the Gap statistic (Algorithm 2) to estimate the cluster count k_hat, and whenever k_hat > 1 partitions clients into 2 clusters via k-means and removes the cluster with larger average suspicious score.
  • supports Source: FLDetector: Defending Federated Learning Against Model Poisoning Attacks via Detecting Malicious Clients · Locator: Section 4.2, Algorithm 2, and Algorithm 3 Lines 8-13, pp. 4-5
Scope #c3-scope-expected-suspicious-score-separation-theorem
Under L-smooth client loss functions, i.i.d. local datasets, and global learning rate alpha < 1 / ((N + 2) L), Lemma 1 bounds the L-BFGS Hessian quadratic form by z^T H_hat^t z <= (N + 1) L ||z||_2^2 and Theorem 1 proves that the expected suspicious score of every benign client i in B is strictly smaller than that of every sign-reversing malicious client j in M: E[s_i^t] < E[s_j^t] (Eq. 5).
  • supports Source: FLDetector: Defending Federated Learning Against Model Poisoning Attacks via Detecting Malicious Clients · Locator: Section 4.4 Theorem 1 (Eq. 5) and Appendix A Lemma 1 & Equations (7)-(26), pp. 4, 10
Limitation #c4-limitation-full-participation-history-and-robust-aggregator-pairing
FLDetector requires tracking each client's previous update g_i^{t-1} across consecutive iterations, exhibits degraded detection accuracy under extreme non-i.i.d. data distributions or adaptive consistency-regularized attacks with small lambda, and must be paired with a Byzantine-robust aggregation rule (such as Krum, Trimmed-Mean, or Median) because vanilla FedAvg can still be backdoored by a single missed malicious client.
  • supports Source: FLDetector: Defending Federated Learning Against Model Poisoning Attacks via Detecting Malicious Clients · Locator: Section 4.5 Eq. (6), Section 5.2 Figures 1-2 & 4a, and Appendix Table 6, pp. 5, 7-9, 11

⚠️ Curated Limitations & Negative Results

  • Requires O(Np) server memory to store N historical global model and update differences and per-client previous updates.
  • Must be paired with a Byzantine-robust aggregation rule rather than plain FedAvg so that any false-negative malicious client after filtering cannot single-handedly backdoor the global model.
