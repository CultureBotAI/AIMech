ITERSSS*

Algorithms AIMech:ITERSSSStar DRAFT
A memory-bounded solution-tree search algorithm for minimax evaluation of a finite uniform alternating game tree that controls an SSS*-style OPEN list through active and inactive entries, capacity-gated MAX-node expansion, and bound-dependent pruning and reactivation.

ITERSSS* denotes the 1986 finite uniform alternating game-tree procedure with active/inactive OPEN entries, solution-tree pruning and memory-controlled passes. It differs from single-agent A*/IDA*/IE, MA*/MAO*/SMA*/MREC/ITS, original Stockman SSS* and the uninspected PARSSS*/MemSSS*/RecSSS*/RecDual* followups. Mechanism #open-entry-budget
In the source’s finite uniform alternating game-tree presentation, ITERSSS* receives an OPEN-entry budget M with M >= M0, where M0 = ceil(d/2) * (b - 1) + 1 for a MAX root, depth d and branching factor b. It initializes the root as LIVE and INACTIVE with an infinite upper-bound value and SPACE = M - 1.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 1 and Section 2, printed pp. 163–164 / PDF pp. 1–2; inclusive M >= M0 premise on printed p. 164
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* initialization on printed p. 164 / PDF p. 2; first(OPEN, FLAG) and phase description on printed p. 165 / PDF p. 3
Mechanism #flag-restricted-selection
OPEN entries carry a value h, a LIVE or SOLVED status, and an ACTIVE or INACTIVE type. Selection takes the greatest h among entries whose type equals FLAG and resolves ties by lexicographically smaller Dewey codes. FLAG begins INACTIVE, switches to ACTIVE on a capacity-blocked MAX expansion or absence of an eligible entry, and does not switch back.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* initialization on printed p. 164 / PDF p. 2; first(OPEN, FLAG) and phase description on printed p. 165 / PDF p. 3
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* nonterminal LIVE MAX branch, printed p. 164 / PDF p. 2
Mechanism #terminal-and-min-advance
A selected LIVE terminal is assigned min(h, v), becomes SOLVED and ACTIVE. A selected LIVE nonterminal MIN node is replaced by its first child, which inherits h, receives LIVE status and takes the current FLAG as its type.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* LIVE terminal, LIVE MIN and SOLVED MAX cases, printed pp. 164–165 / PDF pp. 2–3
Mechanism #capacity-gated-max-expansion
A selected LIVE nonterminal MAX node is replaced by all b children only when SPACE >= b - 1; the children inherit h and FLAG, and SPACE decreases by b - 1. Otherwise that node stays in OPEN as INACTIVE and FLAG becomes ACTIVE.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* nonterminal LIVE MAX branch, printed p. 164 / PDF p. 2
Mechanism #solved-max-sibling-progression
For a selected SOLVED nonroot MAX node, ITERSSS* removes that node and passes its h to the next sibling as LIVE and ACTIVE. After the last sibling it instead inserts the MIN parent as SOLVED and ACTIVE. The displayed branch explicitly excludes the root.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, ITERSSS* LIVE terminal, LIVE MIN and SOLVED MAX cases, printed pp. 164–165 / PDF pp. 2–3
Mechanism #solved-min-purge-and-reactivation
For a selected SOLVED MIN node x, the procedure removes other OPEN entries below its parent whose h is no greater than h(x), releasing one entry of SPACE per removal. If an inactive entry remains below that parent, it activates one at greatest depth and retains x; otherwise it replaces x by the parent as SOLVED and ACTIVE with the same h.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 2, SOLVED MIN branch and inactivesucc helper, printed p. 165 / PDF p. 3; explanatory paragraph on printed p. 166 / PDF p. 4
Mechanism #abstract-space-bookkeeping
Under the displayed conceptual replacements, SPACE equals M minus the number of OPEN entries: initialization uses one entry, one-for-one replacements leave SPACE unchanged, MAX expansion consumes b - 1 entries, and each purge removal releases one. This describes the stable OPEN-entry bookkeeping, not a bound on total implementation memory.

Scope #source-stated-pruning-scope
Using the paper’s solution-tree and fixed-order quantities A_L(x) and B(x), Theorem 4.4 states that A_L(x) >= B(x) is sufficient for ITERSSS* not to examine x. The paper combines this one-way condition with its specified alpha-beta pruning characterization to state inclusion of the terminal nodes examined by ITERSSS* within those examined by that comparator.
  • supports Source: Making Best Use of Available Memory When Searching Game Trees · Locator: Section 4, Definition 4.1 on printed p. 166 / PDF p. 4; Definitions 4.2–4.4, Theorems 4.1–4.4 and omitted-proof statement on printed p. 167 / PDF p. 5
Scope #source-stated-sss-endpoint
For the presented uniform tree, the paper states that setting M = b^ceil(d/2) yields the same operation as SSS*. This is a source-stated sufficient full-memory setting for the parameterized procedure, not a claim that it is the smallest budget producing a matching terminal count on every instance.

⚠️ Curated Limitations & Negative Results

  • The detailed procedure assumes a finite, uniform, alternating MAX/MIN tree with a MAX root, fixed Dewey-code ordering, supplied terminal scores and a finite minimax value. A remark that node coding generalizes to nonuniform trees does not supply a complete variable-branch memory threshold or certify cycles, transpositions, infinite games or learned move ordering.
  • The memory parameter counts OPEN entries in the stable abstract replacement model. It does not bound total bytes, priority-queue overhead, node-code storage or transient allocations. M >= M0 is a premise; no operation below that threshold or extrapolation to depth-zero and other exceptional tree shapes is certified. Informal above-threshold prose is not used to erase the inclusive formal endpoint.
  • The purge and inactivesucc helper use the word successor. Reading it as descendant scope is supported by greatest-depth selection and the parent-subtree explanation, but remains a disclosed interpretation. The source does not specify a tie rule among equally deep inactive candidates; lexicographic first-selection ties do not silently fill that separate gap.
  • The first helper may return null, while the case predicates and loop-termination expression refer to the selected node and its status. Safe null evaluation and short-circuit conventions require implementation choices. The null case changes FLAG; it is not an explicit general failure return or an independently proved remedy for every possible lack of active work.
  • The source omits its formal proofs. It states that SSS* termination and correct root value also hold for ITERSSS*, but the SSS* one-representative-per-solution-tree lemma does not carry over to the ACTIVE subset. Neither the local SPACE arithmetic nor the purge-selection argument replaces a complete proof of ITERSSS* correctness or liveness.
  • Theorem 4.4 gives only a sufficient ITERSSS* non-examination condition. The two-sided SSS* iff characterization, its strict right-hand comparison and an exact memory-dependent pruning law are not transferred. The alpha-beta terminal-set inclusion uses the stated comparator and common order; it does not apply automatically after different move ordering, tie/cutoff rules or implementation changes.
  • The full-memory SSS* endpoint does not make ITERSSS* a global alias of SSS* or alpha-beta, and the source distinguishes it from an alpha-beta/SSS* hybrid. Matching terminal counts at a smaller budget does not establish identical control flow. A general per-instance monotone terminal-count theorem as M increases is not supplied by the displayed experimental trend.
  • The reported evaluation measures average terminal evaluations as a percentage of b^d leaves, using four uniform tree configurations, ten random terminal-value sets per configuration and five M settings. It does not report runtime results. Queue bookkeeping and leaf-evaluation cost can affect time, and no algorithm or benchmark was executed for this draft.
  • The finite synthetic study does not report exact random seeds, a fully specified terminal-value generator distribution, variance or confidence intervals. Its source-reported averages and memory trends do not establish real-game generalization or strict improvement on every input; the paper calls for broader practical evaluation.
  • The inspected defining source is the official five-page 1986 proceedings PDF. Its later digitization metadata does not create a new algorithm version. The earlier MA*/MAO* bibliography uses a different spelling of the first author and a slightly different title; that exact citation remains unchanged alongside the defining PDF metadata. Four cited originals, three retrieved follow-up groups and three additional source questions remain retained without alias, ownership, access or closure decisions.
