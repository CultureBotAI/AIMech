FedEx Weight-Sharing Exponentiated Gradient for Federated Hyperparameter Tuning

Algorithms AIMech:FedExWeightSharingExponentiatedGradientForFederatedHyperparameterTuning DRAFT
Aliases: FedEx, FedEx Federated Hyperparameter Tuning, Weight-Sharing Federated Hyperparameter Optimization, Federated Exponentiated Gradient Hyperparameter Tuning
A federated hyperparameter optimization algorithm (Khodak, Tu, Li, Li, Balcan, Smith, & Talwalkar, 2021) that decomposes federated learning algorithms Alg_a into a server aggregation subroutine Agg_b and a local training subroutine Loc_c with client hyperparameters c in C, and casts client hyperparameter tuning as a neural-architecture-search weight-sharing stochastic relaxation min_{theta in Delta_k, w in R^d} sum_{i=1}^n |V_i| E_{c ~ D_theta} L_{V_i}(Loc_c(T_i, w)) (Eqs. 6-7) over k candidate configurations {c_1, ..., c_k} sampled from a local epsilon-perturbation ball. At each communication round t, each active client i in {1, ..., B} receives shared weights w_t and categorical distribution theta_t, samples c_{ti} ~ D_{theta_t}, computes w_{ti} <- Loc_{c_{ti}}(T_{ti}, w_t), and returns (w_{ti}, c_{ti}, L_{V_{ti}}(w_{ti})); the server updates w_{t+1} <- Agg_b(w_t, {w_{ti}}) and updates theta_t via exponentiated gradient theta_{t+1} propto theta_t odot exp(-eta_t tilde_nabla) using the unbiased importance-weighted stochastic gradient tilde_nabla_j = (sum_{i=1}^B |V_{ti}| (L_{V_{ti}}(w_{ti}) - lambda_t) 1_{c_{ti}=c_j}) / (theta_t[j] sum_{i=1}^B |V_{ti}|) (Algorithm 2, Appendix C.1).
Identity Notes & Concept Scope Distinct from standard Federated Averaging (AIO:FederatedLearning) and Per-FedAvg (AIMech:PerFedAvgModelAgnosticMetaLearningForPersonalizedFederatedLearning), which use fixed client hyperparameters rather than maintaining and updating a categorical distribution D_theta over local training hyperparameters via weight-sharing exponentiated gradient.

4 Claims
Mechanism #weight-sharing-stochastic-relaxation-and-unbiased-exponentiated-gradient
Replacing the personalized tuning objective min_{a=(b,c)} sum_{i=1}^n |V_i| L_{V_i}(Loc_c(T_i, Alg_a({T_j}))) (Eq. 2) with the weight-sharing stochastic relaxation min_{theta in Theta, w in R^d} sum_{i=1}^n |V_i| E_{c ~ D_theta} L_{V_i}(Loc_c(T_i, w)) (Eq. 7) over a categorical distribution D_theta on {c_1, ..., c_k} yields the importance-weighted gradient estimator tilde_nabla_j = (sum_{i=1}^B |V_{ti}| (L_{V_{ti}}(w_{ti}) - lambda_t) 1_{c_{ti}=c_j}) / (theta_t[j] sum_{i=1}^B |V_{ti}|), which is an exact unbiased estimator of nabla_{theta_j} E_{c_{ij} | theta}[L_{V_{ti}}(w_i)] for any baseline lambda_t (Algorithm 2, p. 7; Appendix C.1, p. 16).
  • supports Source: Federated Hyperparameter Tuning: Challenges, Baselines, and Connections to Weight-Sharing · Locator: Section 3, Eqs. (6)-(7), p. 6; Algorithm 2, p. 7; Appendix C.1, p. 16
Mechanism #aruba-online-convex-optimization-step-size-regret-bound
Under Theorem 4.1 (p. 8; proof in Appendix A, p. 14), for tau tasks each consisting of m b-bounded G-Lipschitz convex losses over a compact convex set W of diameter D, running FedEx (Algorithm 2) with B = 1, discretized step-size grid c_j = D / (G j sqrt(m)) for j = 1, ..., k, k^{3/2} = (D G / b) sqrt(tau / (2 m)), bandit exponentiated gradient step-size eta_t = (1 / (m b)) sqrt((log k) / (k tau)), and server averaging alpha_t = 1/t achieves expected task-averaged regret E[R_bar_tau] <= O_tilde(((m / tau)^{1/3} + V) sqrt(m)) (Eq. 10), adapting to the unknown task-similarity V^2 = min_{w in W} (1/tau) sum_{t=1}^tau ||w - w_t^*||_2^2 without knowing V in advance.
  • supports Source: Federated Hyperparameter Tuning: Challenges, Baselines, and Connections to Weight-Sharing · Locator: Section 4, Eqs. (8)-(10), Theorem 4.1, pp. 7-8; Appendix A, p. 14
Scope #local-perturbation-and-wrapper-compatibility-across-fl-methods
Sampling c_1 ~ Unif(C) and c_2, ..., c_k uniformly from a local epsilon-neighborhood [c_1 +- (b - a) epsilon] (with epsilon = 0.1) stabilizes shared-weight training, and wrapping FedEx inside Successive Halving (SHA) or Random Search (Algorithm 3) tunes both server aggregation hyperparameters b and client SGD hyperparameters c (learning rate, momentum, weight decay, local epochs, batch size, dropout, and FedProx mu) across FedAvg, FedProx, Reptile, SCAFFOLD, FedDyn, FedPA, Ditto, and MAML (Section 3, p. 7; Section 5, Table 1, p. 9; Appendix B, pp. 15-16).
  • supports Source: Federated Hyperparameter Tuning: Challenges, Baselines, and Connections to Weight-Sharing · Locator: Section 3, p. 7; Section 5, Table 1, p. 9; Appendix B and C.2, pp. 15-17
Limitation #server-hyperparameter-wrapper-dependency-limitation
FedEx can only directly tune client-side local training hyperparameters c of algorithms that decompose into local fine-tuning Loc_c and server aggregation Agg_b, and must rely on an outer multi-trial wrapper such as Random Search or Successive Halving to tune server-level aggregation hyperparameters b (such as server learning rate and server momentum) as well as FedEx's own discount hyperparameter.
  • supports Source: Federated Hyperparameter Tuning: Challenges, Baselines, and Connections to Weight-Sharing · Locator: Section 3, Limitations of FedEx, p. 7; Appendix C.2-C.3, p. 17

⚠️ Curated Limitations & Negative Results

  • Cannot directly tune server-side aggregation hyperparameters b (such as server learning rate or momentum) without an outer multi-trial wrapper like Successive Halving or Random Search.
  • Sampling configurations uniformly across the full hyperparameter space without local epsilon-perturbation can destabilize shared-weight training.
