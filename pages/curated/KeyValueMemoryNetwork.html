Key-Value Memory Network

Architectures AIMech:KeyValueMemoryNetwork DRAFT
Aliases: KV-MemNN, Key-Value Memory Networks
A neural memory architecture that answers a query by attending to keys and reading corresponding values from supplied key-value memory pairs, with repeated query updates and a learned candidate-answer scorer.

Semantic matching covered 65 AIO and 87 native definitions, with every matched definition read. 7 full annotated AIO node/edge/generated contexts and 3 full native records were inspected. KV-MemNN separates supplied key and value content, not merely two embeddings of the same sentence. It differs from ordinary key-value storage, original hard-retrieval MemNN and the maintained MemN2N configurations. Shared memory terminology does not identify it with an LLM, internal memory cell or NTM read/write controller.

Claims & Grounded Evidence

6 Claims
Mechanism #key-addressing-value-reading
Represent supplied memory as pairs of keys and values. Embed a question with A*Phi_X, score each selected key by its dot product with the query and normalize with softmax. Read the weighted sum of A*Phi_V(value). A is shared in the displayed equations, but key and value feature maps and underlying contents can differ: the representation used to locate information need not be the representation returned. This is soft retrieval, not exact symbolic dictionary lookup.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Section 3.1, PDF pp. 3–4, Figure 1 and key-addressing/value-reading equations
Scope #query-hops-and-output
After a read o, update the query as R_j*(q+o) with a hop-specific learned matrix, and repeat addressing and reading for a fixed number of hops. Score candidate answers with the final query and B*Phi_Y(answer); B may optionally equal A. The source describes cross-entropy training with backpropagation while displaying a hard argmax as the selected answer. Training the answer probabilities does not imply differentiating through that discrete argmax.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Section 3.1, PDF p. 4, query update, candidate answer and training descriptions
Limitation #initial-hash-restriction
The optional initial key-hashing step selects memories sharing a question word whose corpus frequency is below the stated threshold. The subsequent hops repeat addressing and value reading, not hashing. Consequently later queries cannot recover a memory excluded from the initial candidate set in this construction. The source does not establish an empty-set convention here. Softmax weights normalize over the selected slots; duplicating an unmasked slot can change the readout.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Section 3.1, PDF pp. 3–4, key hashing and repeated-hop descriptions; direct constructed examples
Scope #representation-variants
For knowledge-base triples, a key can encode the subject and relation while the value encodes the object; inverse triples use distinct inverse-relation tokens. Document variants use an entire sentence as both key and value, or a word window as key and its center entity as value. Center encoding distinguishes center-word features, while the window-plus-title construction adds title-valued slots and type features. These are engineered representation choices, not a universal learned memory-write procedure. Setting key and value content equal recovers the ordinary memory representation under compatible parameter choices, not every original MemN2N configuration.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Section 3.2, PDF pp. 4–5; Section 3.1, p. 4, relation to end-to-end Memory Networks
Limitation #wikimovies-evaluation-boundary
WikiMovies compares knowledge-base, extracted-triple and document memories in a movie-domain benchmark with question identities separated between splits and a filtered knowledge base intended to align answerability with text. Reported hits-at-one selects one correct answer even when multiple answers exist; it is not recall of all correct answers. Development-set ablations and test results use different reported numbers and representation settings. These comparisons do not establish universal superiority, entity-disjoint generalization or a representation-only causal effect across arbitrary document collections.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Sections 4 and 5.1, PDF pp. 5–8, Tables 2–5
Scope #wikiqa-is-a-separate-protocol
The WikiQA experiment ranks preselected answer sentences and reports MAP and MRR, rather than WikiMovies entity hits-at-one. Its configuration omits hashing, uses window keys with whole-sentence values, and includes next-sentence pretraining on Wikipedia, exact-match features and tuned word dropout. The selected results evaluate this combined pipeline; they do not isolate key-value separation as the sole cause of improvement. Other domains and dialogue are proposed extensions.
  • supports Source: Key-Value Memory Networks for Directly Reading Documents · Locator: Section 5.2, PDF p. 8, Table 6; Section 6, p. 9

⚠️ Curated Limitations & Negative Results

  • The named architecture is distinct from generic key-value storage, original Memory Networks and the original MemN2N parameterizations.
  • Supplied representations, initial candidate selection and output candidates bound the system; arbitrary writable memory, exact retrieval and unlimited context are not established.
  • WikiMovies and WikiQA differ in memory construction, metrics and training enhancements. No author code, training or benchmark replication was performed.
  • All ten pages of arXiv1606.03126v2 were visually read. Other versions and author code were not inspected; constructed examples illustrate boundaries only. DRAFT remains.
