Stochastic local search

Algorithms AIMech:StochasticLocalSearch DRAFT
A configurable family of combinatorial search algorithms that initializes a search position and any memory, then applies a specified neighborhood transition rule until a stopping criterion holds; randomized choices are permitted, with deterministic choices included as degenerate cases.

Claims & Grounded Evidence

6 Claims
Mechanism #neighborhood-search-framework
The selected combinatorial framework specifies a search space, a solution set, a neighborhood relation, initialization, and a step rule. In the authors’ later explicit exposition, the framework also specifies memory and a termination predicate: initialization selects a position and memory state, and each step selects a neighboring position and updated memory according to the specified rule.
  • supports Source: Stochastic Local Search – Methods, Models, Applications · Locator: Section 3.1, physical PDF pp. 59–60, printed pp. 53–54: initialization, neighborhood moves and the five listed components.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Section 54.1, PDF pp. 3–4, printed pp. 1087–1088: seven components, explicit memory and termination, and the working principle.
Scope #randomized-and-deterministic-decisions
Initialization and search steps may use randomized decisions. The framework also includes deterministic local-search procedures by representing deterministic choices as degenerate probability distributions; it does not require uniform sampling or a random decision at every step.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Section 54.1, PDF pp. 3–4, printed pp. 1087–1088: randomized decisions, probability-distribution interpretation, and deterministic special cases.
Mechanism #guidance-memory-and-nonimproving-moves
An evaluation function may guide search, but it need not equal the optimization objective and may change during a run. Memory may influence the next step. Strict improvement of the current candidate is not a requirement of the family: the exposition includes methods that accept worsening moves, while treating iterative improvement as a narrower procedure.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Introduction, PDF p. 2, printed p. 1086, worsening moves and modified evaluation; Section 54.1, PDF pp. 3–4, memory and guidance; Section 54.2, PDF p. 5, printed p. 1089, the separate iterative-improvement procedure.
Scope #constructive-perturbative-and-population-positions
Search positions can encode complete candidate solutions, partial constructions, or sets of candidates. This permits perturbative, constructive and population-based procedures within the same formal framework: extending a partial solution or updating an encoded population can constitute a neighborhood step. These representations do not make the distinct procedures exact aliases.
  • supports Source: Stochastic Local Search – Methods, Models, Applications · Locator: Section 3.1, PDF p. 60, printed p. 54: search spaces need not consist only of complete candidate solutions.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Section 54.1, PDF pp. 3–4, printed pp. 1087–1088: partial-solution neighborhoods and population-valued search positions with set-valued steps.
Mechanism #termination-and-best-encountered-solution
A run initializes its search state and applies the step rule until the supplied termination criterion holds. Under the exposition’s optimization convention, it retains the best feasible solution encountered for return, when such a solution has been encountered. For decision problems, it typically stops upon finding a feasible solution or satisfying another stopping criterion. These conventions specify bookkeeping and termination behavior rather than certify global success.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Section 54.1, PDF pp. 3–4, printed pp. 1087–1088: solution-set conventions, termination predicate, best-so-far return and decision stopping. The feasible-incumbent qualification makes explicit the case in which a returnable solution exists.
Scope #family-and-search-control-boundary
The neighborhood-search family includes simple procedures as well as methods controlled by higher-level strategies. It is not an exact synonym of metaheuristic: the exposition distinguishes simple SLS procedures from high-level guidance and notes that some metaheuristics also use systematic search. The thesis separately introduces generalized local search machines as a way to organize search strategies and their control, rather than making that control representation the definition of every SLS procedure.
  • supports Source: Stochastic Local Search – Methods, Models, Applications · Locator: Chapter 3 introduction and Sections 3.1–3.2 boundary, PDF pp. 59–61, printed pp. 53–55: pure search strategies, higher search control and the GLSM representation.
  • supports Source: Stochastic Local Search Algorithms: An Overview · Locator: Section 54.1, PDF pp. 4–5, printed pp. 1088–1089: explicit contrast between SLS algorithms and metaheuristics.

⚠️ Curated Limitations & Negative Results

  • This record selects the named combinatorial neighborhood-search framework in the inspected thesis and chapter. The bare term local search is often used more narrowly for perturbative search, and its use as the name of an arbitrary embedded optimization routine does not establish the same identity. Continuous-search conventions and the full generalized-local-search-machine model are outside this scoped definition.
  • This is a configurable algorithm family, not a complete executable instance. A concrete procedure must specify its representation, neighborhood, initialization, step and memory rules, evaluation, stopping, tie handling and feasibility conventions. If no feasible solution has been encountered, a best-feasible-solution return is unavailable unless an additional failure or fallback convention is supplied.
  • Current search positions can worsen or recur. Keeping the best encountered value of a fixed, consistently evaluated objective makes that recorded incumbent value non-worsening when an incumbent exists; it does not make every search step improving or prove global optimality. A changing guidance function need not have the same monotonicity.
  • Randomization alone does not guarantee reachability of a solution, irreducibility, finite termination, probabilistic completeness or an approximation guarantee. Such conclusions require additional assumptions on the problem, neighborhood, transition probabilities, initialization and stopping rule. A run stopped by a resource budget can return without finding a feasible or optimal solution.
  • The current search position alone need not be a Markov state when the procedure uses memory or time-dependent rules. An adequate state description may include memory and a clock; this representation does not by itself imply stationarity, detailed balance or sampling from a specified target distribution.
  • Allowing partial solutions and population-valued positions is a formal inclusion, not an assertion that constructive search, evolutionary algorithms, ant-colony methods, strict hill climbing and their particular controllers are identical. The family boundary also differs from the looser term metaheuristic; individual mechanisms and named compositions retain separate identities.
  • The 1998 dissertation supplies the underlying search-space, neighborhood and search-control distinctions; the 2015 author-hosted overview supplies explicit memory, stopping and representation exposition without establishing invention priority. Evidence assessment is limited to the inspected defining passages and selected visuals, not the full dissertation, an unread book definition, all GLSM proofs, author software or benchmark reproduction. No universal performance ranking follows from the framework.
