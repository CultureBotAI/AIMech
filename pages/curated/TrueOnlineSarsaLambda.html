True online Sarsa(lambda)

Algorithms AIMech:TrueOnlineSarsaLambda DRAFT
A linear on-policy action-value control algorithm that combines a Dutch eligibility trace with a correction for changing predictions, using the next action selected by its behavior policy and preserving the specified pre-update action and prediction timing.

Mechanism #linear-on-policy-control
True online Sarsa(lambda) applies the true online temporal-difference construction to a linear action-value estimate Q(s,a)=theta^T psi(s,a), with lambda in [0,1]. Its behavior policy uses the current action-value estimates, for example through epsilon-greedy selection. The source gives action-specific blocks of state features as a common representation, not as a required feature layout.
  • supports Source: True Online TD(lambda) · Locator: Section 5, PDF pp. 7–8, state-action feature extension and control example.
  • supports Source: True Online Temporal-Difference Learning · Locator: Section 4.3, PDF pp. 14–15, action-value control, behavior selection and action-feature construction.
Mechanism #selected-successor-action
Execute the currently carried action A and observe reward R and successor state S_next. Before changing theta, select A_next using the behavior policy and obtain psi_next=psi(S_next,A_next). Compute Q=theta^T psi and Q_next=theta^T psi_next with the pre-update weights, and delta=R+gamma*Q_next-Q. For a terminal successor, use psi_next=0. The bootstrap uses the selected successor action rather than a maximum over successor actions.
  • supports Source: True Online Temporal-Difference Learning · Locator: Section 4.3, PDF p. 15, Algorithm 3 from action execution through the TD-error assignment.
Mechanism #dutch-trace-plus-correction
With constant step size alpha and the unscaled trace convention, update e=gamma*lambda*e_old+psi-alpha*gamma*lambda*(e_old^T psi)*psi. Then update theta_new=theta+alpha*(delta+Q-Q_old)*e-alpha*(Q-Q_old)*psi. The inner product in the trace update uses e_old, while the weight update uses the newly updated e. Both the Dutch trace and the prediction correction are part of the method; changing only the trace in ordinary Sarsa does not generally yield this update.
  • supports Source: True Online Temporal-Difference Learning · Locator: Section 4.3, PDF p. 15, Algorithm 3 trace and weight assignments; Section 4.1, p. 12, Equations 10–12 for the underlying unscaled recurrence.
Mechanism #stored-prediction-and-carried-action
After the weight update, set Q_old to the already computed Q_next, then carry psi_next and A_next into the following transition. Q_old therefore retains a prediction made with the preceding weights; it is not recomputed using theta_new. At the start of each episode reset e=0 and Q_old=0 while retaining the learned weights across episodes. The initially zero trace gives e=psi on the first update, so the dependence on the initial stored prediction cancels in that first weight update.
  • supports Source: True Online Temporal-Difference Learning · Locator: Section 4.3, PDF p. 15, Algorithm 3 episode initialization and final assignments. First-step cancellation is a direct algebraic consequence of its trace and weight recurrences.
Scope #specified-finite-time-correspondence
For a fixed linear feature mapping, matched initial weights and step size, and the same realized action-feature-reward sequence, the Sarsa backward recurrence inherits the specified online lambda-return forward sequence’s finite-horizon weight correspondence. This comparison holds the realized sequence fixed rather than reselecting actions at intermediate forward-replay weights. At lambda=0, e=psi and the separate prediction correction cancels, giving the corresponding one-step linear Sarsa update.
  • supports Source: True Online TD(lambda) · Locator: Section 3, PDF pp. 4–5, online truncated lambda-return sequence; Section 5, pp. 7–8, state-action extension. The shared realized-sequence restriction states the algebraic scope of applying that extension.
  • supports Source: True Online Temporal-Difference Learning · Locator: Section 3.1, PDF pp. 7–8, online forward sequence; Sections 4.1–4.3, pp. 11–15, backward recurrence and Sarsa extension. The lambda-zero reduction follows directly from Algorithm 3.
Scope #continued-credit-and-feature-cost
Algorithm 3 continues its Dutch-trace recurrence without a Watkins nongreedy-action trace reset or a replacing-control rule that clears other actions’ credit. For a linear action-feature vector of dimension d, the dense trace and weight updates use O(d) arithmetic and vector storage per transition. Feature construction and behavior-policy action selection have additional costs; an action-block representation can make d depend on the number of actions.

⚠️ Curated Limitations & Negative Results

  • This identity is the linear on-policy action-value control algorithm, not fixed-policy state-value prediction, the whole Sarsa or TD family, an isolated Dutch trace, original neural MCQ-L, Peng–Williams two-error control, or a greedy Watkins variant. Shared endpoints and source papers do not establish exact aliases.
  • Algorithm 3 uses the constant-alpha unscaled trace convention. A naive varying-alpha substitution is not justified by that pseudocode; a varying-step-size Sarsa extension requires its own matched scaled-trace derivation. Source-display problems documented for the separate Watkins Algorithm 5 are not automatically defects of Sarsa Algorithm 3.
  • Finite-time algebraic correspondence on a matched realized sequence does not establish convergence, monotone policy improvement, optimal control, stationary-policy value accuracy or universal exploration. Replaying a different action sequence changes the comparison. Epsilon-greedy is an example of behavior selection, not by itself a guarantee of coverage or a useful learned policy.
  • The successor action and its prediction are selected and computed before the current weight update. The carried action may cease to be greedy under the updated weights. At a terminal successor, the zero feature vector removes the bootstrap; the printed pseudocode still selects the successor action before its terminal-feature note, so a dummy terminal action or guard is an implementation convention rather than a required real terminal environment action.
  • At lambda=1, interim forward targets can still bootstrap. The terminal full-return forward replay is sequential and does not turn the online procedure into a wait-until-end Monte Carlo algorithm. Continuing undiscounted rewards need appropriate return assumptions. Constant alpha=0 freezes the weights but does not establish a learned solution.
  • The exact backward derivation depends on linearity in the learned weights and a fixed feature mapping. Tabular, binary or real features are compatible, but generic nonlinear or parameter-dependent features do not automatically inherit that correspondence. Dutch traces can be negative or exceed one. Dense O(d) update cost does not imply current-feature-sparsity cost, action-count-free cost or equal wall-clock performance.
  • The 2014 paper names the control extension and reports a mountain-car comparison; the 2016 article supplies the explicit Sarsa pseudocode and further selected experiments. Their empirical claims do not establish universal superiority. Previously retained proof-display qualifications in the 2014 prediction derivation are separate source context, not a new Sarsa implementation defect or an official erratum. The recorded reading is bounded to primary text and selected visuals; no author software or benchmark reproduction is certified.
