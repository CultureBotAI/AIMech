Divide-and-conquer beam-stack search

Algorithms AIMech:DivideConquerBeamStackSearch DRAFT
Aliases: DCBSS
A beam-stack search implementation that retains a small set of search layers and relay information, regenerates missing layers for backtracking, and reconstructs a solution through recursive subproblems.
Identity Notes & Concept Scope DCBSS is the divide-and-conquer implementation of beam-stack search described by Zhou and Hansen. Unlike divide-and-conquer beam search without backtracking, it retains beam-stack range information that permits previously discarded layers to be regenerated and searched further. Claims & Grounded Evidence

2 Claims
Mechanism #search-procedure
Retain the current, previous, successor and relay layers, with relay references used to divide path reconstruction into smaller searches. If chronological backtracking reaches a layer no longer stored, replay from the start using the saved beam-stack ranges to rebuild it. For the general non-unit-cost case in the paper, retain the best goal information and delay path reconstruction until backtracking begins.

Scope #disk-variant-boundary
A separately described external-memory option stores old layers on disk instead of regenerating them. Restoring a layer also requires the previous layer for duplicate detection and repairing relay references; disk use is an optional implementation extension, not part of every DCBSS execution.

⚠️ Curated Limitations & Negative Results

  • Four retained node layers do not imply constant total storage: the beam stack still has depth-dependent entries, and path output, temporary successors and reconstruction state also require memory.
  • Discarding layers trades storage for regeneration and reconstruction work; no universal runtime improvement is implied.
  • The underlying beam-stack pruning, tie handling and bounded-search assumptions still matter. Layered duplicate detection must be matched to the graph setting; the paper distinguishes directed and undirected behavior.
  • The paper summarizes recursive solution recovery and refers to earlier work for implementation details. This record supports the described mechanism, not a complete executable reconstruction implementation.
