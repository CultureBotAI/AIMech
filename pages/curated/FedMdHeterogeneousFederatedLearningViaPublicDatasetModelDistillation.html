FedMD (Heterogeneous Federated Learning via Public-Dataset Model Distillation)

Aliases: FedMD, Heterogeneous Federated Learning via Model Distillation, Digest-and-Revisit Federated Model Distillation
A model-heterogeneous federated learning framework (Li & Wang 2019, Section 3, Algorithm 1, Figure 2) in which each client k in {1, ..., m} designs an arbitrary, privately held neural network architecture f_k, performs initial transfer learning by pre-training f_k on a shared public dataset D_0 = {x_i^0} and fine-tuning on its private dataset D_k, and then collaborates in each communication round through a four-stage public-logit protocol: (1) Communicate each client's class score (logit) predictions f_k(x_i^0) on D_0 to the server; (2) Aggregate the consensus logit vector f_tilde(x_i^0) = (1/m) sum_{k=1}^m f_k(x_i^0) on the server; (3) Distribute f_tilde(x_i^0) back to all clients; and (4) Digest & Revisit by training each local model f_k to match the consensus logits f_tilde(x_i^0) on D_0 (Digest phase) followed by local fine-tuning epochs on private dataset D_k (Revisit phase).

Identity Notes & Concept Scope Distinct from FedDF (AIMech:FedDfEnsembleDistillationForRobustModelFusionInFederatedLearning, Lin et al. 2020), which exchanges model weights and performs ensemble distillation on the server into global prototype architectures rather than communicating only public-dataset logits f_k(x_i^0) and distilling on each client via alternating Digest and Revisit phases; and distinct from FedGKT (AIMech:FedGktGroupKnowledgeTransferForEdgeFederatedLearning, He et al. 2020), which exchanges intermediate feature maps and private-sample logits between small edge encoders and a large server classifier.

Claims & Grounded Evidence

4 Claims
Mechanism #r478-consensus-logit-digest-and-private-revisit-protocol-mechanism
By communicating only class score vectors f_k(x_i^0) evaluated on a shared public dataset D_0 and alternating between a Digest stage (distilling the server-averaged consensus logits f_tilde(x_i^0) = (1/m) sum_{k=1}^m f_k(x_i^0) into each client's model f_k on D_0) and a Revisit stage (fine-tuning f_k on private labeled data D_k), FedMD enables collaborative learning across clients whose neural network depths, channel widths, and architectures differ arbitrarily without revealing model weights or architecture intellectual property (Li & Wang 2019, Section 3, Algorithm 1).
  • supports Source: FedMD: Heterogenous Federated Learning via Model Distillation · Locator: Section 3 (Algorithm 1, Figure 2), p. 3
Scope #r478-transfer-learning-initialization-and-architecture-agnostic-scope
Initializing each heterogeneous client model via transfer learning (training to convergence on public dataset D_0 before fine-tuning on small private dataset D_k) combined with iterative Digest-and-Revisit consensus distillation achieves up to ~20 percentage points higher test accuracy than isolated private training across 10 structurally distinct 2-layer and 3-layer CNN architectures under both IID and non-IID class partitions (Li & Wang 2019, Section 4, Tables 1-2, Figures 3-6).
  • supports Source: FedMD: Heterogenous Federated Learning via Model Distillation · Locator: Section 4 (Tables 1-2, Figures 3-6), pp. 4-6
Application #r478-cross-architecture-emnist-and-cifar-federated-distillation-application
Applied to heterogeneous cross-architecture federated classification using public MNIST with private EMNIST letters and public CIFAR-10 with private CIFAR-100 subsets across 10 distinct CNN architectures (Li & Wang 2019, Section 4, Tables 1-2, Figures 3-6).
  • supports Source: FedMD: Heterogenous Federated Learning via Model Distillation · Locator: Section 4 (Experiments, Tables 1-2, Figures 3-6), pp. 4-6
Limitation #r478-shared-public-dataset-and-per-sample-logit-communication-limitation
Requires a task-relevant shared public dataset D_0 accessible to all clients and incurs per-round communication proportional to |D_0| times the number of classes C (Li & Wang 2019, Sections 3 & 5, pp. 3 & 7).
  • supports Source: FedMD: Heterogenous Federated Learning via Model Distillation · Locator: Section 3 (Algorithm 1), p. 3, and Section 5 (Conclusion and Future Works), p. 7

⚠️ Curated Limitations & Negative Results

  • Requires a labeled or unlabeled public proxy dataset D_0 whose domain is sufficiently related to the clients' private tasks.
  • Does not produce a single server-side model unless the server separately trains a student network on the consensus public logits.
