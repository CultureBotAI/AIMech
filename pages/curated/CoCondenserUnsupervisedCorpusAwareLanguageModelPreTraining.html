coCondenser Unsupervised Corpus-Aware Language Model Pre-Training

Aliases: coCondenser, Corpus-Aware Condenser Pre-Training, Unsupervised Corpus-Aware Condenser for Dense Passage Retrieval
A two-stage unsupervised language model pre-training algorithm for dense passage retrieval that warm-starts from a universal Condenser model (whose head takes the late-backbone [CLS] representation h_cls^late and short-circuited early-backbone token representations h^early for masked language modeling) and continues pre-training on a target search corpus by sampling two random spans (s_{i1}, s_{i2}) from each of n documents in a batch and minimizing the average sum of Condenser masked language modeling loss and a corpus-aware span contrastive loss L_{ij}^{co} = -log [exp(<h_{i1}, h_{i2}>) / sum_{k=1}^n sum_{l=1}^2 I_{ij != kl} exp(<h_{ij}, h_{kl}>)], using a Gradient Cache v_{ij} = dL^{co}/dh_{ij} to decouple large-batch contrastive gradient computation from sub-batch encoder backpropagation before discarding the Condenser head for small-batch dense retriever fine-tuning.

Identity Notes & Concept Scope Distinct from Condenser (Gao & Callan, EMNLP 2021, AIMech:CondenserPreTrainingArchitectureForDenseRetrieval), which uses the late-early short-circuit MLM architecture without any corpus-level contrastive loss over [CLS] inner products; distinct from RocketQA (Qu et al., NAACL 2021, AIMech:RocketQADenoisedHardNegativeSampling), which relies on supervised cross-batch negatives, cross-encoder hard-negative denoising, and synthetic data augmentation during fine-tuning; and distinct from ICT (Lee et al., ACL 2019, AIMech:InverseClozeTask), which contrasts pseudo-queries against context passages using standard Transformer encoders without Condenser short-circuit heads or gradient-cached skip-span contrastive pre-training.

Claims & Grounded Evidence

4 Claims
Mechanism #r752-claim-corpus-span-contrastive-loss
Given a random batch of n documents [d_1, ..., d_n] from the target search corpus, coCondenser samples two random text spans (s_{i1}, s_{i2}) per document and trains their late-backbone [CLS] embeddings h_{ij} with the joint word-and-span objective L = (1/2n) sum_{i=1}^n sum_{j=1}^2 [L_{ij}^{mlm} + L_{ij}^{co}], where L_{ij}^{co} = -log(exp(<h_{i1}, h_{i2}>) / sum_{k=1}^n sum_{l=1}^2 I_{ij != kl} exp(<h_{ij}, h_{kl}>)) pulls spans from the same document together and pushes spans from different documents apart in inner-product space.
  • supports Source: Unsupervised Corpus Aware Language Model Pre-training for Dense Passage Retrieval · Locator: Section 3.2, Equations 6-7, p. 3
Mechanism #r752-claim-gradient-cache-decoupling
To execute 2,000-document (4,000-span) contrastive pre-training updates on four 11GB RTX 2080 Ti GPUs without holding the full batch activation graph in memory, coCondenser runs an initial no-grad forward pass to cache all representation gradients v_{ij} = dL^{co}/dh_{ij} in C = [v_{11}, ..., v_{n2}] and then accumulates parameter gradients (1/2n) sum_{i,j} [v_{ij}^T (dh_{ij}/dTheta) + dL_{ij}^{mlm}/dTheta] over small sub-batches.
  • supports Source: Unsupervised Corpus Aware Language Model Pre-training for Dense Passage Retrieval · Locator: Section 3.3 & Section 4.1, Equations 8-12, pp. 3-5
Application #r752-claim-small-batch-retrieval-application
When fine-tuned with batch size 64 on a single RTX 2080 Ti GPU without cross-encoder denoising or data augmentation, coCondenser achieves 38.2 MRR@10 and 98.4 Recall@1000 on MS-MARCO Passage Dev (and 35.7 MRR@10 / 97.8 R@1000 even without hard negatives), 75.8 R@5 / 84.3 R@20 / 89.0 R@100 on Natural Questions test, and 76.8 R@5 / 83.2 R@20 / 87.3 R@100 on TriviaQA test, outperforming RocketQA trained with batch size 4,096 (37.0 MRR@10, 97.9 R@1000).
  • supports Source: Unsupervised Corpus Aware Language Model Pre-training for Dense Passage Retrieval · Locator: Section 4.2 & Section 5, Tables 1-3, Figure 2, pp. 5-7
Limitation #r752-claim-corpus-specific-pretraining-limitation
Unlike stage-one universal Condenser pre-training, stage-two coCondenser pre-training is corpus-specific and requires running large-batch unsupervised contrastive pre-training (2,000 documents per step) separately on each target retrieval corpus (such as Wikipedia or the MS-MARCO web collection), and without second-round hard negative mining its local ranking precision (35.7 MRR@10) lags behind hard-negative-tuned Condenser (36.6 MRR@10).
  • supports Source: Unsupervised Corpus Aware Language Model Pre-training for Dense Passage Retrieval · Locator: Section 1, Section 4.1, and Section 5, Table 2, pp. 1-2, 4, 7

⚠️ Curated Limitations & Negative Results

  • Requires a second stage of large-batch unsupervised pre-training tailored to each target document corpus (e.g., Wikipedia vs. MS-MARCO) rather than producing a single corpus-agnostic checkpoint.
  • Without second-round hard-negative mining during fine-tuning, coCondenser achieves high recall (97.8 R@1000) but lower top-rank precision (35.7 MRR@10) than hard-negative-tuned Condenser (36.6 MRR@10).
