GPL (Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval)

Algorithms AIMech:GPLGenerativePseudoLabelingForDenseRetrieval DRAFT
Aliases: Generative Pseudo Labeling, GPL Unsupervised Domain Adaptation for Dense Retrieval, GPL MarginMSE Pseudo-Labeling Pipeline
An unsupervised domain adaptation algorithm for dense text retrieval models that adapts a bi-encoder f_theta to an unlabeled target-domain passage corpus by (1) generating synthetic queries Q_i for target passages P_i^+ using a pre-trained sequence-to-sequence query generator, (2) mining hard negative passages P_i^- from the target corpus for each generated query using pre-existing retrievers, and (3) scoring each (Q_i, P_i^+, P_i^-) tuple with a pre-trained cross-encoder CE to compute continuous relevance margins delta_i = CE(Q_i, P_i^+) - CE(Q_i, P_i^-) and training the student bi-encoder via MarginMSE loss L_MarginMSE(theta) = (1/M) sum_{i=0}^{M-1} |hat_delta_i - delta_i|^2.
Identity Notes & Concept Scope Introduced by Wang, Thakur, Reimers, and Gurevych (NAACL-HLT 2022, pp. 2345-2360, arXiv:2112.07577). Distinguished from QGen (Ma et al., 2021; Thakur et al., 2021), which trains on generated queries with binary 0-1 MultipleNegativesRanking loss (MNRL) and degrades when combined with hard negatives, and from InPars (Bonifacio et al., 2022) or Promptagator (Dai et al., 2023), which rely on few-shot LLM prompt generation and top-k likelihood or dual-encoder consistency filtering rather than cross-encoder MarginMSE soft-margin distillation.

Claims & Grounded Evidence

3 Claims
Mechanism #gpl-three-stage-marginmse-distillation-mechanism
For an unlabeled target corpus C (down-sampled to |C_eff| = ceil(250K / 3) when 3*|C| > 250K, with q_avg = ceil(250K / |C_eff|) >= 3 synthetic queries per passage), GPL generates queries Q_i via nucleus sampling from a T5 query generator, retrieves k = 50 hard negatives P_i^- per query using pre-existing dense retrievers, computes cross-encoder logit margins delta_i = CE(Q_i, P_i^+) - CE(Q_i, P_i^-), and trains the student bi-encoder f_theta with dot-product margins hat_delta_i = f_theta(Q_i)^T f_theta(P_i^+) - f_theta(Q_i)^T f_theta(P_i^-) to minimize L_MarginMSE(theta) = (1/M) sum_i |hat_delta_i - delta_i|^2.

  • supports Source: GPL: Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval · Locator: compute_gpl_qpp_and_corpus_size, margin_mse_loss_and_grad_wrt_neg_sim & main
Scope #gpl-false-negative-and-noisy-query-denoising
Replacing QGen's binary 0-1 MultipleNegativesRanking loss (which drops by 2.5 nDCG@10 points on average when trained with mined hard negatives due to false negatives) with continuous cross-encoder MarginMSE soft labels improves average nDCG@10 across six domain-specialized BeIR datasets (FiQA, SciFact, BioASQ, TREC-COVID, CQADupStack, Robust04) from 45.2 (zero-shot MS MARCO) and 48.8 (QGen) to 51.5 (GPL) and 52.9 (TSDAE + GPL), and maintains +3.0 nDCG@10 over zero-shot even at extreme query-generation sampling temperature 10.0.
  • supports Source: GPL: Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval · Locator: Section 5 (Table 1), Section 6.3 (Figure 3), & Section 7 (Table 5), pp. 6-9
  • supports Source: GPL: Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval · Locator: main (Table 5 FiQA false-negative vs. true-negative margin gradient comparison)
Limitation #gpl-multi-stage-training-overhead-limitation
GPL requires a complex multi-stage offline adaptation pipeline—generating 250K synthetic queries, indexing the target corpus for hard-negative mining, and running cross-encoder inference and 140K MarginMSE optimization steps (approximately 9.6 hours on a V100 GPU per 100K steps)—and relies on pre-existing query generation and cross-encoder models pre-trained on a source-domain dataset such as MS MARCO.
  • supports Source: GPL: Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval · Locator: Section 3, p. 3; Section 4.1, p. 4; Section 6.1, pp. 7-8; Section 8 (Conclusion), p. 9

⚠️ Curated Limitations & Negative Results

  • Requires an offline multi-stage adaptation pipeline (query generation, hard-negative mining, cross-encoder scoring, and ~100K-140K MarginMSE optimization steps) for each target corpus.
  • Assumes availability of a source-domain-trained query generator (e.g., DocT5Query) and cross-encoder teacher (e.g., MS MARCO MiniLM cross-encoder).
