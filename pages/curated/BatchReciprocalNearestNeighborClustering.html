Batch reciprocal-nearest-neighbor agglomeration

Algorithms AIMech:BatchReciprocalNearestNeighborClustering DRAFT
Aliases: Reciprocal-neighbor batch clustering, de Rham reciprocal-neighbor clustering
An agglomerative clustering procedure that alternates finding reciprocal nearest-neighbor pairs across the current clusters with merging a batch of such pairs and updating cluster dissimilarities, rather than choosing one globally closest pair or extending a reusable nearest-neighbor chain.

Claims & Grounded Evidence

6 Claims
Mechanism #reciprocal-batch-passes
For each current cluster, find the set of other clusters attaining its minimum dissimilarity. A pair is reciprocal when each belongs to the other’s nearest-neighbor set, equivalently its pair distance attains both minima. The method alternates finding reciprocal pairs, merging a batch, and recomputing nearest-neighbor information until a single cluster remains. Simultaneous disjoint pair merges are a logical batch, not a claim of parallel hardware execution.

Mechanism #matrix-distance-updates
The stored-distance realization updates dissimilarities between the new clusters and remaining clusters. When both endpoints represent newly merged pairs, the paper extends the usual two-cluster recurrence to four original clusters; the linkage coefficients and cluster weights determine that update. This separates the merge-search procedure from the selected linkage criterion.
  • supports Source: La classification hiérarchique ascendante selon la méthode des voisins réciproques · Locator: Sections2.1,3.1–3.3, printedpp136,139–140 / PDFpp3,6–7
Mechanism #vector-realization
For the cited centroid and variance strategies, a second realization retains the observation coordinates, merged representative coordinates and cluster weights and recomputes distances from them. It avoids retaining the full pairwise-distance matrix. The reported N(K+5) storage formula is accounting for that specific implementation with N observations and K variables, not a universal memory bound for every reciprocal-neighbor method.
  • supports Source: La classification hiérarchique ascendante selon la méthode des voisins réciproques · Locator: Sections4.1–4.2 and5, printedpp141–143 / PDFpp8–10
Scope #criterion-and-tie-scope
The source presents exact hierarchical construction for the named monotone single-link, diameter, average and variance strategies, while explicitly treating nonmonotone centroid strategies as heuristic. This does not establish correctness for arbitrary history-dependent recurrences. With ties, reciprocal pairs can overlap; a disjoint selection convention is needed to make a batch executable, and the printed merge-all-pairs instruction does not specify one.

Limitation #passes-and-output-boundaries
A pass need not merge many pairs: the batch procedure can find only one reciprocal pair and therefore require repeated global scans. Few passes in examples do not imply the later nearest-neighbor-chain algorithm’s quadratic bound. Merge heights within a batch need not be globally ordered; constructing a stepwise sequence requires attention to linkage conditions, chronological dependencies and tie handling.

⚠️ Curated Limitations & Negative Results

  • Section2.3 gives the correct mutual-membership definition, but its displayed M shortcuts include a self-membership expression and equate equality of nearest-distance minima with reciprocity. The supported definition requires the pair distance to attain both minima; equal minima alone are insufficient.
  • The finite curator implementation makes tied batches executable through an explicit lexicographic disjoint matching. This is a curator extension, not a tie rule attributed to the source or a claim of identical trees under arbitrary ties.
  • Curator checks cover2,880 four-object cases with distinct initial distances and2,916 cases allowing ties across four linkages. Later merges may introduce ties even in the first set. Stable height ordering is checked against greedy merge admissibility; this is finite evidence, not a universal proof.
  • The original six-point variance example is checked using exact ESS increments:125,212.5,250,1381.25 and19225/12. The source rounds displayed values, including212.5 to213; the rounded tables are not exact recurrence identities.
  • This record does not conflate the batch scan, a reusable reciprocal chain, or cached-bound selection of a globally closest pair. None implies a globally optimal fixed-count partition or automatic selection of a unique cluster count.
  • Complete cited primary PDFs were visually inspected. No author software, CDC benchmark, modern implementation or floating-point behavior was executed; only finite curator calculations were run.
