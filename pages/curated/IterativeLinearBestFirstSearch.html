Iterative linear best-first search

Algorithms AIMech:IterativeLinearBestFirstSearch DRAFT
Aliases: ILBFS
An iterative organization of best-first tree search that explicitly retains a principal path and its immediate children, eagerly collapses a departing branch into backed-up frontier values, and regenerates a selected collapsed branch through conditional value inheritance, as the procedural counterpart of full RBFS described by Felner in 2015.
Identity Notes & Concept Scope This record denotes Felner’s named iterative principal-branch procedure and explicit OPEN/TREE collapse/regeneration organization. The defining paper describes full RBFS as its recursive counterpart with corresponding steps under its conventions. The accepted separation is procedural representation, not a new extensional priority order, solution-quality advantage or universal implementation-equivalence result. ILBFS is the source abbreviation; RBFS, SRBFS, IE and generic best-first search are not aliases. Conditional backed-up inheritance, depth-first ties, the high-level ancestry discrepancy and root/dead-end/graph interfaces remain explicit. The later 2024 versions and pinned code are research context for preserved limitations, not replacements for the 2015 definition. Claims & Grounded Evidence

6 Claims
Mechanism #principal-branch-and-frontier
The explicit TREE representation retains a principal branch of internal nodes and their immediate children, while OPEN contains its frontier. With branching bounded by b, retained depth bounded by d and bounded per-node data, this path-and-children representation uses O(b*d) node storage, which is depth-linear when b is fixed.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF p.4, principal-branch description and Figure 2; PDF p.6, Table 1 and continuum discussion
Mechanism #minimum-frontier-selection
The low-level loop selects a node with minimum stored value from OPEN and checks for a goal before changing the retained branch. It then generates children of the selected node and inserts them into OPEN and TREE. Root, tie and exhaustion conventions must be supplied consistently with the qualified source outline.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF p.5, Algorithm 2 lines 1–6 and 12–17
Mechanism #eager-bottom-up-collapse
When the newly selected node is not a child of the previously expanded node, the operational prose and low-level listing collapse the departing branch bottom-up: back up the minimum child value, return that parent to OPEN, remove its children from OPEN and TREE, and continue toward the parent of the new best node. Collapse is triggered by a branch switch rather than by exhausting a fixed memory budget.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF p.4, Case 2 and Figure 2(c–d); PDF p.5, collapse explanation and Algorithm 2 lines 7–11; PDF p.6, continuum discussion
Mechanism #conditional-value-inheritance
For a generated child C, the low-level rule first assigns its static evaluation f(C). Only when the selected parent has F(best)>f(best) does it raise a child value below F(best) to that stored parent value. Ordinary iterations with this conditional rule carry out the source’s regeneration process; the rule is not unconditional pathmax on an initial visit.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF p.5, Algorithm 2 lines 12–16 and Observations 1–2; PDF p.6, opening restore discussion
Scope #depth-first-tie-conditioned-collapse-marker
For its particular collapse process, the paper argues that depth-first tie handling makes a departing collapsed branch satisfy F(B)>f(B), and uses the F>f test to identify prior collapse. The paper explicitly extends these observations to nonmonotone static evaluations. This is a source-qualified invariant under that process and tie convention, not a universal property of every collapse policy.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF p.5, Observations 1–2, proof and footnote 8
Scope #explicit-counterpart-to-full-rbfs
The paper presents ILBFS as an iterative counterpart of the compared full RBFS formulation, with corresponding search steps under its conventions. ILBFS represents the principal branch and alternatives explicitly in OPEN/TREE; RBFS retains corresponding information through recursive frames and a competitive bound. The distinction is procedural organization, without a claimed new search ordering or solution-quality advantage over that counterpart.
  • supports Source: Position Paper: The Collapse Macro in Best-First Search Algorithms and an Iterative Variant of RBFS · Locator: PDF pp.6–7, RBFS and its relation to ILBFS; PDF p.6, Figure 3

⚠️ Curated Limitations & Negative Results

  • The high-level Algorithm 1 line 8 reverses the sibling/ancestor description of the branch to collapse relative to the Case 2 prose and low-level Algorithm 2. The mechanism above follows the latter two explicitly; the literal high-level discrepancy is retained and no repaired implementation is certified.
  • The printed low-level outline leaves root/NULL-parent conventions, empty-child minima and complete infinity/exhausted-frontier handling incompletely specified. The compared RBFS listing explicitly includes an empty-successor return and a finite-value guard. ILBFS goal testing precedes collapse, and the outline is not a complete production interface for every dead end or unsolvable input.
  • The path-and-children description does not provide a complete general graph duplicate-state, cycle or reopening policy. Generic best-first discussion assumes reopening for inconsistent heuristics, but that is not a demonstrated ILBFS graph implementation. No completeness, optimality or termination guarantee is extended here to arbitrary infinite spaces, zero-cost cycles or unspecified goal/cost assumptions.
  • A generic collapse stores only a frontier summary and is described as lossy compression. Its monotone bounded-search restoration discussion must not be promoted to an exact inverse for arbitrary collapsed subtrees. The ILBFS-specific F>f regeneration argument depends on its own branch-switch and depth-first tie conventions; changing those conventions requires a new argument.
  • O(b*d) is a retained-node model with bounded branching, attained depth and per-node data, not a fixed maximum-node budget or a total-byte guarantee. State encodings, heuristic tables, explicit queues, transient allocations and any duplicate/transposition tables require separate space accounting; SMA* memory-budget properties do not follow from shared backup/deletion ideas.
  • The same-step comparison is to the full RBFS formulation reproduced in this source under compatible selection and tie conventions. It is not a global alias claim for every RBFS version or for SRBFS or Russell’s Iterative Expansion. In particular, unconditional first-visit inheritance and conditional inheritance can differ with nonmonotone evaluations, and the cited 1993 RBFS journal version remains a retained version question.
  • The later 2024 text describes its depth-first tie rule as taking the node inserted first, while the inspected pinned comparator favors greater creation times for equal F and its child timestamps increase. This is a prose/code distinction at commit e0e5ec40751ab9108d9b0a36bbc81ac843f5ca8c; a complete trace-equivalence result or proof of cycle freedom is not supplied by that static comparison.
  • The 2024 heap discussion conflates observing a minimum with extracting it and restoring heap order. Its arbitrary-node deletion procedures include linear search/removal work; for positive k their stated O(k*n+n) and O(k*(n+log n)) totals are both O(k*n) as n grows. No general asymptotic or measured runtime superiority is inferred from that discussion.
  • The 2024 versions report different experiment designs and one v1 caption conflicts with its memory axis. The v2 table does not show a slower ILBFS time in every row. The pinned notebook source, imports and start-inclusive path-length bins do not establish reproduction of the v2 move-length experiment, and traced Python allocations are not total process memory. No code, notebook or benchmark was run for this draft.
  • The 2015 work already reports an implementation, so the 2024 first-implementation assertion is retained as a source conflict rather than a historical fact. Pedagogical ease is not an evaluated learning outcome. The later epsilon paragraph’s RBFS_CR label does not establish equivalence to the distinct 2015 histogram method; source versions, author-name/publication metadata and all bibliography/retrieval questions remain explicit research context.
