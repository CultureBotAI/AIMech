Aliases: BasicILS(N)
A ParamILS algorithm-configuration method that compares candidate configurations using cost estimates on the same fixed number of target-algorithm runs, paired by problem instance and random seed.
Definition Evidence
  • supports Source: ParamILS: An Automatic Algorithm Configuration Framework · Locator: Sections3.1–3.2 and Algorithm Framework1/Procedure2, PDF pp.7–9 (printed273–275); Section5.1, PDF pp.14–15; capping qualifications in Section4, PDF pp.11–14; Section10, PDF pp.34–36
Identity Notes & Concept Scope BasicILS(N) specializes the ParamILS framework by fixing the comparison sample size N. N counts instance/seed evaluations, not necessarily distinct instances. It differs from FocusedILS, which grows evaluation prefixes adaptively, and from random search, which does not use ParamILS neighborhood perturbation and local search. Claims & Grounded Evidence

1 Claim
Mechanism #method
Use ParamILS initialization, randomized one-exchange local search, perturbation, nonworsening acceptance and random restart. Implement each comparison by obtaining the chosen cost statistic for both configurations on the first N pairs in the shared instance/seed sequence, reusing cached compatible target-algorithm runs. The uncapped comparison returns true when the first configuration’s estimate is no greater than the second’s. Track the best encountered configuration under that empirical objective. The fixed comparison budget is independent of the overall time or iteration budget used to stop the configurator.

⚠️ Curated Limitations & Negative Results

  • The 2009 formulation has a finite configuration domain; numerical parameters require discretization. Objective, run cutoff and training-instance distribution affect the selected configuration. Independent held-out evaluation is needed to assess generalization; no universal solver speedup is asserted.
  • The printed first-improvement loop accepts the supplied non-strict comparison. Equal-cost neighboring configurations can therefore cycle under a literal reading; this record does not assert unconditional termination of that loop or executable equivalence to a software release.
  • Adaptive capping is a separable acceleration, not the defining identity of this search/comparison method. Section4 describes trajectory-preserving and more aggressive alternatives. Procedure4 prints a max operation inconsistent with shortening the run cutoff described in the prose, and uses inconsistent cutoff symbols; the printed routine is not treated as verified executable code.
  • A small fixed N can give unreliable rankings and overfitting; a large N increases evaluation cost and reduces search progress at a fixed time budget. These are experimental-design tradeoffs, not a guarantee that one N is optimal.
