pFedHN (Personalized Federated Hypernetworks)

Algorithms AIMech:PFedHnPersonalizedFederatedHypernetworks DRAFT
Aliases: pFedHN, Personalized Federated Hypernetworks, pFedHN-PC
A personalized federated learning method (Shamsian, Navon, Fetaya, & Chechik 2021, Section 3, Algorithm 1, Equations 2-4) in which a central server maintains a shared hypernetwork h(v_i; varphi) and low-dimensional client embedding vectors v_i in R^{d_e}, generates personalized target network weights theta_i = h(v_i; varphi) for sampled client i, receives the client's multi-step local displacement Delta theta_i = tilde_theta_i - theta_i, and updates both the hypernetwork parameters varphi and client embedding v_i on the server via the chain-rule surrogate gradient (nabla_varphi theta_i)^T Delta theta_i and (nabla_{v_i} theta_i)^T Delta theta_i.
Identity Notes & Concept Scope Distinct from Per-FedAvg (AIMech:PerFedAvgPersonalizedFederatedLearningWithTheoreticalGuarantees, Fallah et al. 2020) and pFedMe (AIMech:PFedMePersonalizedFederatedLearningWithMoreauEnvelopes, T. Dinh et al. 2020), which transmit and regularize a single shared d-dimensional model init across all clients rather than generating client-conditioned parameters theta_i = h(v_i; varphi) from a low-dimensional client descriptor v_i on the server.

Claims & Grounded Evidence

4 Claims
Mechanism #r443-chain-rule-delta-update-and-pfedhn-pc-decoupled-head
Replacing the single-step gradient nabla_{theta_i} L_i(theta_i) in the chain-rule derivative nabla_varphi L_i = (nabla_varphi theta_i)^T nabla_{theta_i} L_i with the k-step local parameter change Delta theta_i = tilde_theta_i - theta_i (Eq. 4) avoids backpropagating through k steps of client optimization while never transmitting the hypernetwork varphi over the network; the pFedHN-PC extension (Section 3.1) generates only the feature extractor via h(v_i; varphi) while maintaining a strictly local classification head per client to handle distinct local label spaces.
  • supports Source: Personalized Federated Learning using Hypernetworks · Locator: Section 3 Equations 3-4, Algorithm 1 & Section 3.1 Personal Classifier (pFedHN-PC), pp. 9491-9493
Mechanism #r443-generalization-bound-and-unseen-client-embedding-adaptation
By Theorem 1 (Section 4), for n clients with m samples each, an L_h-Lipschitz hypernetwork with parameter dimension k = dim(varphi) and L-Lipschitz target models with embedding dimension d_e = dim(v_i), uniform generalization scales with effective complexity (k + n d_e) / (n m) rather than target parameter dimension d / m, and novel unseen clients at test time can personalize by optimizing only their low-dimensional embedding vector v_new in R^{d_e} with varphi frozen (Section 5.3, Figure 2).
  • supports Source: Personalized Federated Learning using Hypernetworks · Locator: Section 4 Analysis (Theorem 1) & Section 5.3 Generalization to Novel Clients (Figure 2), pp. 9493-9497
Limitation #r443-server-side-hypernetwork-memory-and-output-layer-scaling-limitation
Generating all target network weights theta_i in R^d directly from the hypernetwork requires an output projection of size O(d_hidden * d) on the server (mitigated by chunked weight generation across target layers), and the server must maintain stateful per-client embedding vectors v_1, ..., v_n.
  • supports Source: Personalized Federated Learning using Hypernetworks · Locator: Section 3 Architecture Details & Appendix B Hypernetwork Parameterization
Application #r443-heterogeneous-cifar-omniglot-and-office-caltech-personalization-application
Applied to personalized federated image classification across CIFAR-10, CIFAR-100, Omniglot, and heterogeneous feature-shift domains in Office-Caltech10 under both label-distribution and input-distribution shifts.
  • supports Source: Personalized Federated Learning using Hypernetworks · Locator: Section 5 Experiments (Tables 1-4, Figures 2-3), pp. 9494-9498

⚠️ Curated Limitations & Negative Results

  • Requires server-side backpropagation through the hypernetwork Jacobian at each communication round.
  • Requires storing a persistent embedding vector v_i on the server for each participating client.
