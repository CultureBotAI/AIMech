Recursive best-first search

Algorithms AIMech:RecursiveBestFirstSearch DRAFT
Aliases: RBFS
A recursive search algorithm that explores the best stored subtree alternative within an upper bound and conditionally passes a previously backed-up value to regenerated children, retaining path and sibling information instead of the full best-first frontier.
Identity Notes & Concept Scope RBFS denotes Korf’s full refinement of SRBFS. A backed-up value greater than the node’s static value signals previous exploration; only then do child values inherit the maximum of that backed-up value and their own static evaluations. Unconditionally replacing every child value by the maximum with its parent’s value would lose this distinction for nonmonotone evaluation functions. No normalized identity match was found across the 442 AIO and 124 prior native records; ignored-inclusive text hits in the main checkout were prior discovery leads, source citations and search-order contrasts, plus incidental dependency substrings, not existing concept records.

Claims & Grounded Evidence

2 Claims
Mechanism #search-procedure
For a node with static value f and stored value V, initialize each child from its static value unless V exceeds f, in which case use the maximum of V and the child’s static value. Recurse into the child with the smallest stored value using the smaller of the inherited bound and the next-best sibling value. Back up the returned value, reorder the children and switch subtrees when an alternative becomes preferable.

The later primary paper reproduces the conditional inheritance rule and the bound obtained from competing stored subtree values before introducing separate re-expansion-control variants.

⚠️ Curated Limitations & Negative Results

  • The paper’s best-first-order statement concerns newly expanded search-tree nodes. Previously expanded paths may be regenerated in depth-first order.
  • Path and sibling storage is O(bd) for branching factor b and maximum depth d under the paper’s model; linear-in-depth storage assumes bounded b and fixed-size node data.
  • Numerous distinct evaluation values can cause substantial regeneration overhead. The memory saving does not establish an A-star-equivalent runtime bound.
  • If a cycle does not increase the evaluation value, explicit current-path cycle checking is needed to avoid looping; the method is not a global closed-list duplicate-elimination algorithm.
