MREC

Algorithms AIMech:MREC DRAFT
A recursive heuristic search algorithm that retains an explicit search graph within available additional memory, explores unstored successors virtually when that storage is unavailable, and backs up remaining-cost estimates between bounded recursive passes.
Identity Notes & Concept Scope MREC denotes Sen and Bagchi's 1989 recursive best-first memory-controlled procedure, with an explicitly stored graph and virtual unstored successors, backed-up remaining costs and a separate recursion stack. It is not LIMMARK, REC_A, MA*, A* with an OPEN list, learned IDA*IM, or a generic A*/IDA* hybrid title; the zero-additional-graph-memory endpoint does not make the complete method an IDA* alias. Preserve the inclusive UPDATE recursion test versus the adjacent strict prose comparison; MREC’s early goal-found return bypasses the final node-bound backup assignments. Mechanism #stored-and-virtual-search
EXPLORE descends recursively from the start. At an explicit tip it adds successors and edges when memory permits; otherwise UPDATE explores successors without adding them to the explicit graph. The algorithm uses no OPEN list.
  • supports Source: Fast Recursive Formulations for Best-First Search That Allow Controlled Use of Memory · Locator: Section 2, printed pp. 297–298 / PDF pp. 1–2; EXPLORE and UPDATE
Mechanism #retained-graph-estimates
EXPAND initializes a newly stored successor estimate with its heuristic value and records an edge to that successor; when the successor is already in the explicit graph, it adds the edge without creating another stored node. UPDATE uses the stored estimate when available and the heuristic estimate otherwise.
  • supports Source: Fast Recursive Formulations for Best-First Search That Allow Controlled Use of Memory · Locator: Section 2, printed p. 298 / PDF p. 2; EXPAND and UPDATE pseudocode
Mechanism #inclusive-recursion-and-backup
In the printed UPDATE pseudocode, a successor is explored recursively when its current estimate plus transition cost is less than or equal to the current node bound. The recursive bound is the current bound minus that cost. If no goal terminates the traversal early, the returned node bound is the minimum resulting successor estimate plus transition cost, and a stored node receives that updated bound; the goal-found branch instead records the path and returns before those final backup assignments.
  • supports Source: Fast Recursive Formulations for Best-First Search That Allow Controlled Use of Memory · Locator: Section 2, printed p. 298 / PDF p. 2; UPDATE pseudocode, inclusive test newb + c(n,n_i) <= bnode
Scope #extra-memory-control
The parameter M describes storage additional to the implicit recursion stack. With no additional graph storage the method operates in the IDA* manner; with storage available it retains explicit graph information between recursive passes rather than becoming an OPEN-based A* implementation.
  • supports Source: Fast Recursive Formulations for Best-First Search That Allow Controlled Use of Memory · Locator: Abstract and Sections 1–2, printed pp. 297–299 / PDF pp. 1–3; property 1 and property 2

⚠️ Curated Limitations & Negative Results

  • M is additional storage beyond the implicit recursion stack; M = 0 does not mean zero total memory. The paper does not specify a portable byte-level accounting of graph nodes, edges and runtime overhead.
  • The operational recursion condition here follows the inclusive comparison in the UPDATE pseudocode. The explanatory paragraph below it instead prints a strict comparison with confusing subscripts, so the two presentations are not silently treated as identical.
  • The source states a minimum-cost-solution property for admissible heuristics, but this record does not certify general termination or solution existence. The main procedure repeats exploration until a goal is found and does not specify a general unsolvable-instance exit.
  • No completeness or cost-optimality guarantee is extended here to infinite search spaces, zero-cost cycles or arbitrary negative costs. Conditions such as finite cost contours, a positive lower bound on edge costs, and a goal heuristic of zero would require an explicit independent argument; they are not attributed to an uninspected theorem in this paper.
  • Retaining an explicit graph permits reuse of stored successor identities, but it is not a claim that every encountered state remains in a global closed set. Virtual successors are deliberately not retained when additional storage is unavailable.
  • Even with ample storage, the source distinguishes MREC from A* by expansion order and potentially by the returned solution path. The configurable MREC identity is not collapsed into A* or IDA* merely because the algorithms share cost estimates or a memory endpoint.
  • LIMMARK, the proposed removal of nonpromising stored nodes, and the AND/OR extension REC_A are separate variants or follow-up methods. Their uninspected implementation details and cyclic AND/OR guarantees are not included in this MREC record.
  • The reported experiments concern particular puzzle, traveling-salesman, knapsack and artificial-tree setups. Retaining more graph information adds update work and does not establish a universal runtime improvement, a universal memory/time tradeoff, or identical results for another implementation.
