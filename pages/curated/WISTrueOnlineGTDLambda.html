WIS-TO-GTD(lambda)

Algorithms AIMech:WISTrueOnlineGTDLambda DRAFT
A linear off-policy state-value prediction adaptation of true online GTD(lambda) that derives componentwise main-weight step sizes from feature usage, retains a scalar auxiliary step size, and couples main and auxiliary Dutch traces with a gradient-correction trace.

Mechanism #linear-off-policy-host-adaptation
WIS-TO-GTD(lambda) estimates a target policy state value V_t(s)=theta_t^T*phi(s) from behavior-policy transitions. The source uses fixed linear features, current action ratios rho_t=pi(A_t|S_t)/b(A_t|S_t), state-dependent discount gamma and bootstrapping lambda in [0,1]. Its usage adaptation replaces the main scalar step size of the true-online GTD host by a component vector while retaining scalar beta for the auxiliary weights. This is prediction machinery, not an action-selection or policy-improvement rule.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Sections 3 and 5, author PDF pp. 3–5, prediction setting; Section 6, p. 7, host adaptation and main versus auxiliary step sizes; Appendix A.7, p. 18, Algorithm 3.
Mechanism #usage-state-and-explicit-reciprocal-versions
Let ⊙ denote componentwise multiplication, h_t=1-eta*(phi_t⊙phi_t) and q_t=gamma_t*lambda_t. Update u_(t+1)=h_t⊙u_t+rho_t*(phi_t⊙phi_t)+(rho_t-1)*q_t*(h_t⊙v_t) and v_(t+1)=rho_t*q_t*(h_t⊙v_t)+rho_t*(phi_t⊙phi_t), using old v_t in both right sides. The main step vector alpha_(t+1) is computed from new u_(t+1). The paper assigns a reciprocal at zero the value zero. The pinned WTOGTD code instead replaces an exactly zero denominator by one before taking its reciprocal, giving step size one at that component. These are explicitly different boundary conventions.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Section 2, author PDF p. 3, componentwise division convention; Equations 22–24, p. 6; Appendix A.7, p. 18, Algorithm 3 usage lines.
  • supports Source: Author implementation of WIS-TO-GTD: WTOGTD class in wis-td-experiments · Locator: WTOGTD.step, lines 37–45: old usage state, dtemp zero replacement and reciprocal alpha.
Mechanism #three-traces-with-pinned-correction-history
In the pinned code, with a_t=alpha_(t+1)⊙phi_t and q_t=gamma_t*lambda_t, the main trace is e_t=rho_t*[q_t*e_(t-1)+(1-rho_t*q_t*phi_t^T*e_(t-1))*a_t]. The auxiliary trace is e_w,t=rho_(t-1)*q_t*e_w,(t-1)+beta*(1-rho_(t-1)*q_t*phi_t^T*e_w,(t-1))*phi_t. The accumulating correction trace is e_grad,t=rho_t*(q_t*e_grad,(t-1)+phi_t). Thus the first and third traces use current rho, while the auxiliary Dutch trace uses stored previous rho. The code and the 2014 host use the correction trace’s own old history; the printed 2015 Algorithm 3 instead displays old main e_(t-1) in that recurrence. The selected explicit correction-history equation here is the pinned-code interpretation.
  • supports Source: Author implementation of WIS-TO-GTD: WTOGTD class in wis-td-experiments · Locator: WTOGTD.step, lines 49–53, and stored-ratio assignment at line 58.
  • supports Source: Off-policy TD(λ) with a true online equivalence · Locator: Section 6, first-author PDF p. 7, Theorems 3–4 and final algorithm display: two Dutch traces and own-history accumulating correction trace.
  • contradicts Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Appendix A.7, author PDF p. 18, Algorithm 3, displayed e_grad recurrence uses e_(t-1) without the gradient superscript; contrasts with the pinned-code equation stated here.
Mechanism #pre-update-predictions-and-coupled-weights
Form delta_t=R_(t+1)+gamma_(t+1)*theta_t^T*phi_(t+1)-theta_t^T*phi_t before updating weights. With o_t the stored previous next-state prediction, the pinned code updates theta_(t+1)=theta_t+delta_t*e_t+(theta_t^T*phi_t-o_t)*(e_t-rho_t*a_t)-gamma_(t+1)*(1-lambda_(t+1))*(w_t^T*e_grad,t)*(alpha_(t+1)⊙phi_(t+1)), and w_(t+1)=w_t+rho_t*delta_t*e_w,t-beta*(w_t^T*phi_t)*phi_t. Both right sides use old w_t and the same pre-update delta. It then stores rho_t and the pre-update theta_t^T*phi_(t+1). Along a contiguous feature trajectory, o_t equals theta_(t-1)^T*phi_t, rather than a next prediction recomputed after the current weight update.
  • supports Source: Author implementation of WIS-TO-GTD: WTOGTD class in wis-td-experiments · Locator: WTOGTD.step, lines 47–59: prednext, delta, sequential theta/w right sides and stored prediction/rho.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Appendix A.7, author PDF p. 18, Algorithm 3, delta and theta/w update lines; the correction trace is separately version-qualified.
Scope #qualified-zero-lambda-and-on-policy-reductions
When all lambda values are zero, the traces reduce to e_t=rho_t*(alpha_(t+1)⊙phi_t), e_w,t=beta*phi_t and e_grad,t=rho_t*phi_t, and the prediction-difference term vanishes. With matched usage, reciprocal and initialization conventions, the resulting update is WIS-GTD(0). When all rho values are one, beta=0 and w_0=0, the auxiliary weights remain zero and the main update reduces to usage-based true-online TD under matched feature, reciprocal and boundary conventions. Beta=0 alone with arbitrary nonzero w_0 does not generally remove the main auxiliary correction.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Section 6, author PDF p. 7, on-policy relationship; Appendix A.7, p. 18, Algorithms 2, 3 and 5. The zero-w condition and lambda-zero reduction follow from the displayed updates.

⚠️ Curated Limitations & Negative Results

  • The selected explicit implementation is the author WTOGTD class at commit d73d441ca34c546cae79c9289104a68238c9b7ce. Its own-history accumulating correction trace differs from the old-main-trace operand printed in the 2015 Algorithm 3. The code supports a version-specific interpretation, not a formal erratum or blanket paper/code equivalence. It remains distinct from WIS-TD with provisional state, accumulating WIS-GTD, ordinary true-online GTD and the on-policy usage-based hosts.
  • The paper reciprocal at zero is zero; the code uses one at an exactly zero usage denominator. Bare eta>=0 does not guarantee positive or bounded usage and reciprocal steps for arbitrary features and ratios. For example, scalar u_0=1, eta=2 and phi_0=rho_0=1 give u_1=0. With zero initial weights and traces, R_1=1 and gamma_1=0, the paper convention gives theta_1=0 while the code convention gives theta_1=1. This hand boundary example lies outside sufficiently small eta positivity conditions; it is not an observed experimental failure or a convergence result.
  • The pinned constructor initializes theta, w, all three traces, v, previous rho and previous prediction to zero, with uniform configured initial usage. Its initepisode method clears only the main trace z. Usage and auxiliary/correction histories are not thereby fully reset. A contiguous continuing trajectory and an episodic caller that resets only z need not have the same state carry; no universal full-reset protocol is inferred from the printed algorithm.
  • Meaningful finite importance ratios require suitable target-policy action support under behavior; relevant features, rewards and steps must also be well defined. The implementation does not enforce all such conditions. Main alpha is componentwise and auxiliary beta remains scalar. With beta=0 and zero initial w, the gradient correction vanishes and cannot distinguish competing correction-trace recurrences; beta=0 alone is insufficient for arbitrary nonzero w.
  • Old v, old w, pre-update theta and the previous pre-update next-state prediction are part of the stated timing. Substituting new w in the main correction or updating the stored prediction from new theta changes that procedure. A next lambda of one removes the explicit gradient-correction term but does not alone make the method an exact Monte Carlo average or normalized WIS estimator.
  • The source leaves convergence analysis of the new WIS/usage algorithms for future work. The 2014 host’s exact linear sampled forward-view construction and the 2015 usage correspondence do not establish a general convergence, stability, monotonic improvement or exact per-transition objective-gradient theorem for this implementation. The separate WIS-TD forward-weight theorem is not silently transferred to WIS-TO-GTD.
  • The scope is fixed linear state-value prediction. Nonlinear or learned features, action-value control and policy improvement require separate evidence. The record makes no experimental performance or author-test-pass claim; reading source code and configuration files is not executing or reproducing them.
  • The selected paper evidence is the acquired eighteen-page combined author copy of the 2015 paper and Appendix A plus the specific first-author-hosted 2014 GTD version. Native-text version comparisons and the embedded PDF creation date do not certify every formula or establish a scientific revision date. The commit-pinned implementation scope does not certify all repository callers, dependencies, later versions or proofs.
