Diff Pruning

Algorithms AIMech:DiffPruning DRAFT
Aliases: Structured Diff Pruning, Adaptive Diff Pruning, L0-Regularized Diff Pruning, Difference Vector Pruning for Transfer Learning
A parameter-efficient transfer learning algorithm that formulates task-specific fine-tuning as learning a sparse difference ('diff') vector delta_tau added to frozen shared pre-trained parameters theta via theta_tau = theta + delta_tau. To learn which coordinates to modify during training, Diff Pruning decomposes delta_tau = z_tau (*) w_tau using a stretched Hard-Concrete gate z_tau = min(1, max(0, s_tau * (r - l) + l)) with s_tau = sigma(log u - log(1 - u) + alpha_tau), u ~ U(0, 1), l < 0, and r > 1, and optimizes a closed-form differentiable expected L0-norm penalty E[||delta_tau||_0] = sum_{i=1}^d sigma(alpha_{tau,i} - log(-l/r)). In its Structured Diff Pruning extension, parameters are partitioned into G matrix/bias groups {g(1), ..., g(G)} with per-group gates z_tau^j so delta_{tau,i}^j = z_{tau,i} * z_tau^j * w_{tau,i} and E[||delta_tau||_0] = sum_{j=1}^G sum_{i in g(j)} sigma(alpha_{tau,i} - log(-l/r)) * sigma(alpha_tau^j - log(-l/r)). After training, exact budget control (e.g., t% = 0.5% nonzeros) is achieved by projecting delta_tau onto the target L0-ball via magnitude pruning on delta_tau followed by fixed-mask fine-tuning.
Identity Notes & Concept Scope Distinct from standard weight pruning and Movement Pruning (AIMech:MovementPruning), which mask the pre-trained parameters theta directly (setting masked weights to zero) rather than masking the additive task difference delta_tau = theta_tau - theta (which preserves the unpruned pre-trained value theta_i when delta_{tau,i} = 0). Also distinct from low-rank additive adapters such as LoRA (AIMech:LowRankAdaptation), which constrain delta_tau to a low-rank matrix product rather than an L0-sparse coordinate/group-gated difference vector.

Claims & Grounded Evidence

3 Claims
Mechanism #diff-pruning-hard-concrete-l0-and-structured-group-gates
Diff Pruning relaxes the binary mask on delta_tau = z_tau (*) w_tau using a stretched Hard-Concrete distribution on (l, r)^d (with l = -1.5, r = 1.5, w_tau initialized to 0, and alpha_tau initialized to 5), yielding the differentiable expected L0 penalty sum_{i=1}^d sigma(alpha_{tau,i} - log(-l/r)); Structured Diff Pruning multiplies each element mask by a matrix/bias-group gate z_tau^j (393 groups in BERT_LARGE), increasing the average percentage of completely zeroed parameter groups at 0.5% sparsity from 6.3% (non-structured) to 28.1% (structured) (Table 3).
  • supports Source: Parameter-Efficient Transfer Learning with Diff Pruning · Locator: Section 3.1-3.3, pp. 3-4; Section 4.3, pp. 4-5; Section 6.2, Table 3, pp. 6-7
Application #diff-pruning-l0-ball-projection-glue-and-squad-performance
By projecting delta_tau onto an exact L0-ball via magnitude pruning and fine-tuning with the nonzero mask fixed, Structured Diff Pruning matches full fine-tuning of BERT_LARGE on the GLUE test server (80.6 average score vs. 80.6 for full fine-tuning, 79.4 for unstructured Diff Pruning, and 75.5 for non-adaptive diff pruning) while modifying only 0.5% of parameters per task (13.6 MB storage for positions + weights vs. 49.0 MB for 3.6% Adapters and 1297.0 MB for full fine-tuning), and achieves 93.2 F1 on SQuAD v1.1 at 1.0% sparsity vs. 90.8 F1 for full fine-tuning.
  • supports Source: Parameter-Efficient Transfer Learning with Diff Pruning · Locator: Section 3.2, p. 3; Section 5.1-5.2, Table 1 & Figure 1, pp. 5-6; Section 6.4 & 6.6, Tables 4 & 6, pp. 7-8
Limitation #diff-pruning-training-memory-speed-and-index-storage-limitation
During training, Diff Pruning requires extra GPU memory to store and optimize the auxiliary log-alpha parameters alpha_tau alongside the dense weight vector w_tau, runs approximately 1.5x to 2x slower per minibatch than standard fine-tuning, and requires storing integer coordinate indices alongside nonzero float weights for each task's compressed diff vector.
  • supports Source: Parameter-Efficient Transfer Learning with Diff Pruning · Locator: Section 6.6-6.7, pp. 7-8, Table 6

⚠️ Curated Limitations & Negative Results

  • Requires optimizing both alpha_tau and w_tau during training, increasing training memory overhead and slowing per-minibatch training speed by approximately 1.5x to 2x relative to standard fine-tuning (Section 6.7).
  • Requires storing integer coordinate indices in addition to nonzero floating-point weights for each task's sparse diff vector, and suffers a 3.5-point GLUE validation drop (from 84.9 to 81.4) if post-projection fixed-mask fine-tuning is omitted (Section 6.4, Footnote 16; Section 6.6).
