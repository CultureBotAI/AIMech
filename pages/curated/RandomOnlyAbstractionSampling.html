Random-only abstraction for abstraction sampling

Mathematical Methods AIMech:RandomOnlyAbstractionSampling DRAFT
Aliases: Random-only abstraction sampling, simpleRand abstraction, Purely random abstraction sampling
A randomized abstraction rule for graphical-model sampling that uniformly permutes the current search nodes and divides that order into groups of nearly equal cardinality, within which the surrounding sampler selects and importance-weights representatives.

Retain the simpleRand abstraction component: uniformly shuffle the current node set and split the resulting sequence into balanced-cardinality groups. This is separate from the AOAS traversal and estimator, from the value-ordered randVB cuts, and from randomized context hashing RandCB. Generic tree sampling supplies representative-weight logic rather than this partition rule. Bare RAND and random sampling are excluded as ambiguous aliases.

Claims & Grounded Evidence

6 Claims
Mechanism #shuffle-and-balanced-groups
For N current nodes and an integer group count k with 1 <= k <= N, draw a uniformly random permutation. Let b=floor(N/k) and e=N mod k. Cut the sequence into k groups, giving the first e groups b+1 nodes and the others b nodes. This uses node identities and cardinalities without sorting by heuristic or proposal values.

Mechanism #weighted-selection-remains
The randomization changes the partition rule. In AOAS, the representative within each group is still sampled using the normalized proposal proportional to w*g*h*r and its weight becomes w/p for the actual selection probability p. Random group assignment therefore does not make representative selection uniformly distributed across the frontier, and does not remove dependence on the surrounding heuristic and weight updates.

Scope #distinct-randomization-laws
simpleRand fixes balanced group sizes after shuffling node order. The value-based randVB scheme instead selects cut positions in value-sorted order and permits unequal group sizes. RandCB hashes full context assignments into abstract states. These randomization laws are distinct; sharing a randomization step is not an identity mapping.
  • supports Source: Value-Based Abstraction Functions for Abstraction Sampling · Locator: Main Section 4 context-based paragraph, Section 4.2 randVB and Algorithm 5, Section 5 and Algorithm 6, PDF pp.4,6–7 / printed pp.2864,2866–2867
Scope #linear-partition-cost
The paper states O(N) time and space for the simpleRand partition step. This bound concerns shuffling and grouping current nodes, with k bounded by N. It excludes heuristic preprocessing, generating those nodes and the surrounding AOAS traversal or repeated probes.
  • supports Source: Value-Based Abstraction Functions for Abstraction Sampling · Locator: Main Section 5 Complexity, PDF p.7 / printed p.2867; Algorithm 1, PDF p.3 / printed p.2863
Limitation #diversity-is-not-a-variance-guarantee
The authors motivate random groups by their potential to expose otherwise rarely selected nodes to more favorable competitors. This is a design intuition, not a guarantee of uniform inclusion, minimum estimator variance or finite-run accuracy. Correct weighting and proposal support remain necessary for expectation claims of the surrounding estimator.

Limitation #evaluation-reference-limits
The reported RAND results use AOAS and weighted mini-bucket heuristics on five graphical-model benchmark families. Some reported settings select granularity by observed benchmark error; runs without a positive estimate use a mini-bucket fallback. Large-problem error uses a reference from long RAND runs rather than exact partition functions. The main text labels that reference 10 hours while supplemental legends say 100 hours, and the supplemental exact-DBN budget differs from the main setting. These results do not establish an independently exact reference or universal superiority.

⚠️ Curated Limitations & Negative Results

  • This record is the simpleRand abstraction component, not a complete estimator or every randomized abstraction. Bare RAND is not an alias. Random group membership alone does not identify value-based cuts, context hashing, a learned abstraction or a clustering objective.
  • The stated cardinality formula uses a nonempty frontier and 1 <= k <= N. A larger cap requires an explicit singleton/empty-group convention; the separate supplemental singleton wrapper is presented for value-ordered abstractions and is not asserted here as simpleRand pseudocode. k=0 is invalid. Correct uniform shuffling is assumed.
  • In a finite four-node example, all24 permutations give three balanced pairings equally often. With contributions1,1,9,9 and uniform selection within each pair, every partition estimates20 in expectation; random pairing has variance256/3 while value-homogeneous pairing has variance0. This illustrates lack of universal variance reduction, not a benchmark result.
  • Unequal proposal masses1,2,3,4 produce unequal marginal inclusion probabilities under the same random pairings. Conditional selection must use its actual probability, and positive contributions require positive support. Zero/all-zero proposal handling and numerical stability remain implementation responsibilities.

The separate19-page extended background and OpenReview copies were not fully read; source-comparison and partial static implementation reading are documented in the ledger. No author program, training run, hardware measurement or benchmark replication was executed.
