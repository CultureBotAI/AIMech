HyDE Hypothetical Document Embeddings

Algorithms AIMech:HyDEHypotheticalDocumentEmbeddings DRAFT

Aliases: HyDE, Hypothetical Document Embeddings, Zero-Shot Dense Retrieval via Hypothetical Document Embeddings
A training-free zero-shot dense retrieval method that decomposes relevance modeling into an instruction-following natural language generation step and an unsupervised document-document similarity step: given a test query, an instruction-following language model generates N hypothetical documents that exemplify relevant answer patterns (even if factually ungrounded), an unsupervised contrastively pretrained encoder maps those hypothetical documents and the query into a dense query vector by averaging their embeddings, and real corpus documents are retrieved via inner-product similarity in the document embedding space.

Identity Notes & Concept Scope Distinct from document-to-query data augmentation methods such as Promptagator (AIMech:PromptagatorFewShotDenseRetrievalDataGeneration) and InPars (AIMech:InParsInContextDataAugmentationForInformationRetrieval), which generate synthetic queries from real documents offline to train retrievers or rerankers, whereas HyDE requires no model training or corpus access beforehand and instead translates each incoming query online into hypothetical documents so that retrieval occurs purely in an unsupervised document-document contrastive embedding space.

Claims & Grounded Evidence

4 Claims
Mechanism #hyde-generative-hypothetical-document-pivoting
Given a query q_{ij} and task instruction INST_i, HyDE samples N hypothetical answer passages d_hat_k ~ InstructLM(q_{ij}, INST_i) and computes the query representation as the expectation average v_hat_{q_{ij}} = (1/(N+1)) (sum_{k=1}^N f(d_hat_k) + f(q_{ij})) using an unsupervised contrastive document encoder f = enc_con.
  • supports Source: Precise Zero-Shot Dense Retrieval without Relevance Labels · Locator: Section 3.2, pp. 3-4, Equations 2-8
Mechanism #hyde-dense-bottleneck-hallucination-filtering
Because the unsupervised contrastive encoder f maps text into a compact dense vector trained for document-document similarity, it acts as a lossy bottleneck that filters out hallucinated factual details in the generated hypothetical passages while grounding the resulting vector to real corpus documents via inner-product search.
  • supports Source: Precise Zero-Shot Dense Retrieval without Relevance Labels · Locator: Section 1 & Section 3.2, pp. 2 & 4
Application #hyde-zero-shot-web-beir-and-multilingual-application
Without any relevance labels or model fine-tuning, HyDE pairing InstructGPT with Contriever or mContriever substantially outperforms BM25 and standalone Contriever across TREC DL19/DL20 web search, six BEIR low-resource retrieval tasks, and multilingual retrieval in Swahili, Korean, Japanese, and Bengali on Mr.TyDi.
  • supports Source: Precise Zero-Shot Dense Retrieval without Relevance Labels · Locator: Section 4.1-4.4, pp. 4-6, Tables 1-3
  • supports Source: Precise Zero-Shot Dense Retrieval without Relevance Labels (Crossref metadata) · Locator: DBLP bibliographic record Luyu Gao et al. ACL 2023
Limitation #hyde-online-llm-generation-latency-and-low-resource-limitation
HyDE requires invoking an instruction-following generative language model at query time for every user query and its effectiveness degrades when the generative model or contrastive encoder is under-trained on low-resource languages or specialized entity domains.
  • supports Source: Precise Zero-Shot Dense Retrieval without Relevance Labels · Locator: Section 4.3-4.4 & Section 6, pp. 5-7

⚠️ Curated Limitations & Negative Results

  • Online generation of N hypothetical passages per query using a large language model increases query-time latency and compute cost compared to a standalone bi-encoder.
  • Assumes a unimodal embedding expectation over generated documents, which can be suboptimal for highly ambiguous queries with multiple distinct interpretations.
