Instance-Dependent Prompt Generation

Algorithms AIMech:IDPGInstanceDependentPromptGeneration DRAFT
Aliases: IDPG, M-IDPG-PHM, S-IDPG-PHM, Multi-Layer Instance-Dependent Prompt Generation
A conditional parameter-efficient prompt-tuning method for pre-trained language models that generates continuous soft prompts W_p(T, x_i) = G(M(x_i), T) in R^{t x d} conditioned on each input sequence representation M(x_i) in R^d using a lightweight two-layer bottleneck perceptron G whose down-projection W_1 in R^{m x d} and up-projection W_2 in R^{(t d) x m} are decomposed via Parameterized Hypercomplex Multiplication (PHM) Kronecker sums W = sum_{j=1}^n A_j otimes B_j, with multi-layer variant M-IDPG sharing W across all Transformer layers while maintaining layer-specific bias prompts.
Identity Notes & Concept Scope Introduced by Zhuofeng Wu, Sinong Wang, Jiatao Gu, Rui Hou, Yuxiao Dong, V. G. Vinod Vydiswaran, and Hao Ma (NAACL 2022, arXiv:2204.04497) as Instance-Dependent Prompt Generation (IDPG / S-IDPG-PHM / M-IDPG-PHM). Distinct from static Prompt Tuning and SPoT (AIMech:SPoTSoftPromptTransfer), which use a fixed input-independent prompt per task (recovered as the degenerate case W = 0 in IDPG where only the second-layer bias is active); from ATTEMPT (AIMech:ATTEMPTAttentionalMixturesOfSoftPrompts), which interpolates pre-trained source-task prompts via sub-query attention rather than generating prompts through a PHM bottleneck MLP; and from Hyperdecoder (AIMech:HyperdecoderInstanceSpecificDecoderAdapter), which generates decoder adapter weights from encoder hidden states rather than layer-wise soft prompt tokens.

Claims & Grounded Evidence

4 Claims
Mechanism #idpg-bottleneck-prompt-generator-and-static-degeneracy
Given a sentence representation M(x_i) in R^d of input x_i, IDPG generates a t-token continuous prompt W_p(T, x_i) = G(M(x_i), T) via a two-layer bottleneck generator with hidden size m << d requiring m(d+1) + t d(m+1) parameters before compression, and strictly generalizes task-specific prompt tuning since setting the projection weights W to zero leaves the second-layer bias term t x d as a static task-specific prompt.
  • supports Source: IDPG: An Instance-Dependent Prompt Generation Method · Locator: Section 1 & Section 3.1, Equations (1)-(3), pp. 2-3
Mechanism #idpg-phm-kronecker-decomposition-and-multilayer-sharing
Replacing the dense generator matrices W_1 in R^{m x d} and W_2 in R^{(t d) x m} with Parameterized Hypercomplex Multiplication (PHM) layers W = sum_{i=1}^n A_i otimes B_i (with A_i in R^{n x n} shared across layers) reduces single-layer generator parameters from 1.5M (S-IDPG-DNN) to 105K (S-IDPG-PHM) for d=1024, m=256, t=5, n=16, while multi-layer M-IDPG-PHM shares W across N=24 layers with layer-specific biases in 134K trainable parameters (0.04% of RoBERTa-Large).
  • supports Source: IDPG: An Instance-Dependent Prompt Generation Method · Locator: Section 3.2.1-3.2.2, Equation (4), Table 2 & Appendix A.1.2, pp. 4, 6, 11-12
Application #idpg-nlu-and-few-shot-benchmark-performance
Across ten NLU benchmarks (MPQA, Subj, CR, MR, SST-2, QNLI, RTE, MRPC, STS-B, QQP) on RoBERTa-Large, M-IDPG-PHM achieves 91.9 average score with 134K trainable parameters, outperforming standard prompt tuning (88.8) by +3.1 points and P-tuning v2 (90.3) by +1.6 points, and in few-shot settings (K in {100, 500, 1000}) outperforms prompt tuning by +2.5, +2.1, and +2.0 points respectively.
  • supports Source: IDPG: An Instance-Dependent Prompt Generation Method · Locator: Section 4.2-4.4, Tables 1-3, pp. 5-7
  • supports Source: IDPG: An Instance-Dependent Prompt Generation Method (Crossref metadata) · Locator: NAACL 2022 bibliographic record
Limitation #idpg-two-forward-pass-and-low-resource-variance-limitation
When using the pre-trained language model itself to compute M(x_i), IDPG requires two forward passes at inference time unless M(x_i) is cached or replaced by lightweight GloVe embeddings (M-IDPG-PHM-GloVe), and exhibits elevated initialization variance in extreme low-resource regimes (e.g., standard deviation 4.6 on MPQA at K=100).
  • supports Source: IDPG: An Instance-Dependent Prompt Generation Method · Locator: Section 3.1, Section 4.4 & Section 4.5.1, pp. 3-4, 6-7

⚠️ Curated Limitations & Negative Results

  • Computing the instance representation M(x_i) with the pre-trained Transformer requires an extra forward pass at inference time unless M(x_i) is pre-cached or substituted with static word embeddings such as GloVe.
  • In extreme few-shot regimes (K = 100), generator initialization sensitivity can cause higher run-to-run variance on small datasets such as MPQA.
  • Combining residual connections and LayerNorm simultaneously inside the single-layer PHM prompt generator degrades accuracy compared to PHM alone or PHM with LayerNorm only.
