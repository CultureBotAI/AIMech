Black-Box Tuning (BBT) for Language-Model-as-a-Service

Algorithms AIMech:BBTBlackBoxTuningForLanguageModelAsAService DRAFT
Aliases: Black-Box Tuning, BBT, BBT Derivative-Free Subspace Prompt Tuning, CMA-ES Intrinsic-Subspace Black-Box Prompt Tuning
A derivative-free continuous prompt optimization method for Language-Model-as-a-Service (LMaaS) inference APIs that exploits the low intrinsic dimensionality of large pretrained language models by parameterizing a D-dimensional continuous prompt p in R^D as an increment p = A z + p_0 over initial vocabulary embeddings p_0 via a fixed uniform random projection matrix A in R^{D x d} from a low-dimensional subspace z in [-5, 5]^d (with d << D), and iteratively optimizes z* = arg min_{z in Z} L(f(A z + p_0; X_tilde), Y_tilde) using the Covariance Matrix Adaptation Evolution Strategy (CMA-ES) querying only forward-pass masked-token logits Y_hat = f(p; X_tilde).
Identity Notes & Concept Scope Distinct from gradient-based Prompt Tuning (Lester et al., EMNLP 2021, AIMech:PromptTuning) and P-Tuning v2 (AIMech:PTuningV2DeepContinuousPromptTuning), which require backward-pass gradient access to the language model, and from RLPrompt (Deng et al., EMNLP 2022, AIMech:RLPromptReinforcementLearningDiscretePromptOptimization), which optimizes discrete vocabulary tokens via a policy network and Soft Q-Learning rather than continuous prompt increments in a random linear subspace via CMA-ES.

Claims & Grounded Evidence

4 Claims
Mechanism #r727-claim-random-subspace-cma-es
To make derivative-free optimization tractable for a continuous prompt of length L = 50 and dimension D = 50 x 1024 = 51,200, Black-Box Tuning optimizes z in [-5, 5]^d in a d = 500 dimensional subspace mapped by a He-uniform random matrix A in R^{D x d} around initial prompt p_0, sampling offspring z_i^(t+1) ~ m^(t) + sigma^(t) N(0, C^(t)) via CMA-ES (population size lambda = 20) to minimize multi-class cross-entropy or margin hinge loss L_Hinge(y_hat, y_tilde) = sum_{i != y_tilde} max(0, gamma + y_hat_i - y_hat_{y_tilde}) over API-returned masked logits.

Mechanism #r727-claim-decoupled-client-resource-overhead
Because Black-Box Tuning updates only the d-dimensional CMA-ES distribution parameters on the user side, its client optimization cost is decoupled from the parameter count of the server-side PTM, requiring only 30 MB of user RAM (no client GPU needed), 6-22 KB upload and 0.25-1 KB download per query on SST-2 and AG's News (compared to 6,016-27,392 KB download for Feature-BiLSTM).
  • supports Source: Black-Box Tuning for Language-Model-as-a-Service · Locator: Section 4.2 & Appendix C, Table 4, pp. 6-7, 14-15
Application #r727-claim-few-shot-accuracy-application
In the 16-shot per class setting with RoBERTa-large across 7 NLU benchmarks (SST-2, Yelp Polarity, AG's News, DBPedia, MRPC, SNLI, RTE), Black-Box Tuning (within an 8,000 API call budget and MNLI prompt pre-training for sentence-pair tasks) achieves 83.90% average score, outperforming gradient-free Manual Prompt (62.56%), In-Context Learning (59.36%), and Feature-BiLSTM (68.29%) as well as gradient-based Prompt Tuning (74.42%), P-Tuning v2 (70.47%), and full Model Tuning (78.88%).
  • supports Source: Black-Box Tuning for Language-Model-as-a-Service · Locator: Section 3.4 & Section 4.2, Table 3, pp. 4, 6-7
Limitation #r727-claim-many-class-and-subspace-limitation
Black-Box Tuning trails full Model Tuning by 10.18 points on 14-class DBPedia (87.80% vs. 97.98%) where the number of classes is large, requires the server API to accept continuous prompt vector injections Az + p_0 alongside token IDs, and degrades if the random subspace dimension d is too small (e.g., d = 100 underfits) or too large (e.g., d = 1000 slows CMA-ES convergence and overfits).
  • supports Source: Black-Box Tuning for Language-Model-as-a-Service · Locator: Section 4.2-4.3 & Section 5, Table 3, Figure 3, pp. 6-8

⚠️ Curated Limitations & Negative Results

  • Underperforms full-model fine-tuning on classification tasks with a large number of classes (such as 14-class DBPedia, 87.80% vs. 97.98%) and requires sentence-pair tasks (SNLI, RTE, MRPC) to be initialized from an MNLI pre-trained prompt embedding p_0 to match or beat full fine-tuning.
  • Requires the server-side inference API to accept continuous prompt embedding vectors p = A z + p_0 and return candidate label-word logits rather than strictly text-in/text-out strings.
