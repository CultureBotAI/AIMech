Piggyback Binary Weight-Mask Multi-Task Adaptation

Algorithms AIMech:PiggybackBinaryWeightMaskMultiTaskAdaptation DRAFT
Aliases: Piggyback, Piggyback Weight Masking, Piggyback Binary Mask Multi-Task Adaptation, Differentiable Binary Weight Masking for Fixed Backbones
A multi-task and continual neural network adaptation algorithm that freezes all weight matrices W of a pretrained backbone network, associates each weight w_{ji} with a trainable real-valued mask variable m^r_{ji} passed through a hard deterministic binary threshold m_{ji} = 1[m^r_{ji} >= tau] during the forward pass y = (W odot m) x, updates m^r via the straight-through gradient estimator delta_m = (delta_y . x^T) odot W during backpropagation, and discards m^r after training to retain only a 1-bit-per-parameter binary mask m per task.
Identity Notes & Concept Scope Distinct from PackNet (Mallya & Lazebnik, CVPR 2018, AIMech:PackNetIterativePruningContinualLearning), which prunes and modifies network weights sequentially and degrades as tasks are added, from Edge-Popup (Ramanujan et al., CVPR 2020, AIMech:EdgePopupUntrainedSubnetworkScoreOptimization) and SupSup (AIMech:SupSupSupermasksInSuperposition), which discover fixed-sparsity top-k% subnetworks in randomly initialized networks without task-specific classification heads, and from Residual Adapters (Rebuffi et al., NeurIPS 2017), which insert additional trainable convolutional filter banks.

Claims & Grounded Evidence

4 Claims
Mechanism #r720-claim-straight-through-binary-mask
Piggyback maintains real-valued mask weights m^r initialized uniformly above the binarizer threshold (e.g., m^r = 1e-2, tau = 5e-3 so all weights are initially active) and updates them with Adam using the straight-through gradient of the thresholded mask delta_m_{ji} = delta_y_j w_{ji} x_i, which scales proportionally to |W|; after training, discarding m^r leaves a binary mask requiring only 1 bit per 32-bit parameter (~3.12% storage overhead per task).
  • supports Source: Piggyback: Adapting a Single Network to Multiple Tasks by Learning to Mask Weights · Locator: Section 3, Equations 4-7, pp. 5-6
Mechanism #r720-claim-task-order-agnostic-continual
Because Piggyback never alters the underlying backbone weights W and learns an independent binary mask per task, it is completely immune to catastrophic forgetting, agnostic to task ordering (unlike PackNet, whose error increases by 4-7% when a task is added fifth instead of first), and imposes no upper bound on the number of tasks that can piggyback onto the backbone.
  • supports Source: Piggyback: Adapting a Single Network to Multiple Tasks by Learning to Mask Weights · Locator: Section 2 & Section 4, Table 2, pp. 3, 7-8
Application #r720-claim-visual-decathlon-and-fcn-application
Across VGG-16, ResNet-50, DenseNet-121, and Wide ResNet-28-4 backbones, Piggyback matches or outperforms dedicated per-task fine-tuned networks on CUBS, Stanford Cars, Flowers, WikiArt, Sketch, and Places365, achieves a 2838 cumulative score on the 10-task Visual Decathlon challenge with only a 1.28x total parameter ratio, and reaches 61.41 mIOU vs. 61.08 mIOU for full fine-tuning on PASCAL VOC FCN semantic segmentation.
  • supports Source: Piggyback: Adapting a Single Network to Multiple Tasks by Learning to Mask Weights · Locator: Section 4 & Section 6, Tables 2, 3, 4, and 8, Figure 4, pp. 7-10, 13-14
Limitation #r720-claim-no-cross-task-sharing-and-bn-limitation
Because each task's binary mask operates independently on the fixed initial backbone, tasks added later cannot transfer or share newly learned features with one another, and on deep batch-normalized backbones (ResNet-50, DenseNet-121) under large domain shifts such as WikiArt, keeping batch-normalization parameters fixed leaves a 4-5% error gap unless task-specific batch-normalization parameters (~1 MB overhead) are also trained.
  • supports Source: Piggyback: Adapting a Single Network to Multiple Tasks by Learning to Mask Weights · Locator: Section 4, Section 5.3, and Section 7, Tables 4 and 7, pp. 9-10, 12-13, 15

⚠️ Curated Limitations & Negative Results

  • Added tasks cannot benefit from features learned on other added tasks because all tasks only mask the fixed initial backbone weights.
  • Performance depends heavily on the diversity of the initial backbone pretraining (e.g., ImageNet initialization strongly outperforms Places365 or random initialization), and deep networks with Batch Normalization suffer a 4-5% accuracy gap on large domain shifts (such as WikiArt) unless task-specific Batch Normalization statistics and parameters are also updated.
