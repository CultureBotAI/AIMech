Simplified memory-bounded A-star search

Aliases: SMA*
A node-budgeted best-first tree-search algorithm that generates one successor at a time, propagates evaluation values through pathmax and completed-node backup, and deletes selected high-cost nodes while retaining parent bounds for later regeneration.
Definition Evidence
  • supports Source: Efficient Memory-Bounded Search Methods · Locator: Sections 3–3.3, manuscript pp. 3–4 / PDF pp. 3–4; SMA*, BACKUP and Figure 2
Identity Notes & Concept Scope SMA* denotes Russell's 1992 simplified memory-bounded A* tree procedure, with a node budget, incremental successor generation, pathmax, guarded completed-node backup and least-promising-node deletion with retained parent bounds. It is distinct from unrestricted A*, frontier-cap beam search, earlier MA*/MAO*, MREC and IE; later textbook variants and generic graph duplicate handling are not imported. The exact source parent guard and original storage/completeness qualifications remain part of its scope. Claims & Grounded Evidence

4 Claims
Mechanism #best-leaf-and-single-successor
SMA* chooses the deepest least-f-cost leaf in OPEN, tests that selected node for a goal, and generates its next successor. The successor receives the maximum of the parent’s backed-up f value and its own g + h value.
  • supports Source: Efficient Memory-Bounded Search Methods · Locator: Section 3.1, manuscript p. 3 / PDF p. 3; SMA*(start) pseudocode
Mechanism #completed-node-backup
When the selected node has no unexamined successors, SMA* calls BACKUP. In the displayed procedure, a completed node that has a parent receives the least successor f value; if that value changes, BACKUP is called on its parent under the same completion-and-parent guard. A node whose successors are all in memory is removed from OPEN.
  • supports Source: Efficient Memory-Bounded Search Methods · Locator: Section 3.1, manuscript p. 3 / PDF p. 3; completed-node definition, SMA* and BACKUP pseudocode
Mechanism #bounded-pruning-and-regeneration
After successor generation raises USED above MAX, the displayed algorithm deletes the shallowest highest-f-cost node in OPEN, removes it from its parent’s successor list and reinserts that parent in OPEN if necessary. Parent bounds and successor bookkeeping allow later regeneration without retaining every deleted descendant’s information.
  • supports Source: Efficient Memory-Bounded Search Methods · Locator: Sections 3.1–3.3, manuscript pp. 3–4 / PDF pp. 3–4; pruning steps and Figure 2 discussion
Scope #node-budget-and-bookkeeping
MAX specifies the number of nodes that can be accommodated and USED tracks nodes in memory. Each node stores g, h and f, the minimum f among examined successors, and information indicating the next successor to generate.
  • supports Source: Efficient Memory-Bounded Search Methods · Locator: Section 3.1, manuscript p. 3 / PDF p. 3; paragraph after BACKUP, continuing at top of right column

⚠️ Curated Limitations & Negative Results

  • MAX is a node count, not a byte limit. Per-node fields, successor bookkeeping, OPEN data structures, recursive backup and transient successor construction must be accounted for separately in any concrete memory implementation.
  • The paper’s optimal-solution statement requires MAX to accommodate at least the nodes on an optimal solution path. Its introductory setting uses admissible heuristic estimates and enforces monotone f values through pathmax; the statement is not an unconditional guarantee at arbitrarily small memory budgets.
  • The inspected treatment concerns trees; the author explicitly excludes the treatment of transpositions in graphs. No graph closed-list, reopening rule or complete duplicate-detection procedure is asserted for this SMA* record.
  • No general termination result is supplied here for infinite trees, zero-cost cycles or negative costs. Finite-contour, positive-cost and goal-zero-heuristic premises would need to be stated and justified before extending the source’s claims to such cases.
  • Constant retained information per node loses some information about deleted descendants. Regenerating a subtree can therefore use a weaker inherited value than a value previously known deeper in that subtree.
  • The record follows the displayed 1992 pseudocode. It does not import the depth-limit-to-infinity rule found in later presentations, or claim that an uninspected textbook or implementation uses identical tie, dead-end and backup behavior.
  • MA* and IE remain separate source questions. The paper’s MA* sketch is explicitly approximate and sometimes describes how SMA* works instead; similarities between IE and existing RBFS require a complete control-flow and tie/dead-end comparison before any alias decision.
  • The experiments use modified 8-puzzle conditions and do not establish universal superiority over A*, IDA*, MA* or other memory-bounded searches. The paper does not provide an exhaustive MA* comparison.
