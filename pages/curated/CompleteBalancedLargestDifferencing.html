Complete balanced largest differencing

Algorithms AIMech:CompleteBalancedLargestDifferencing DRAFT
Aliases: Complete BLDM
A complete anytime two-way number-partitioning search that carries signed effective cardinalities through difference and sum branches, uses paired initialization before largest-residual branching, and prunes against a prescribed subset-size difference while retaining the best valid partition.

Complete BLDM is the named Mertens two-phase search with signed effective-cardinality state and pruning. It explores same-side alternatives to initial adjacent pairs as well as later largest-residual pairs. Balanced targets obtain the BLDM first solution; the same source pseudocode handles other feasible absolute cardinality targets. This is distinct from the BLDM heuristic, PDM and unconstrained CKK. Mechanism #signed-residual-state
Represent each residual by its nonnegative value, a signed effective cardinality and reconstructible original-item groups. Original items start with effective cardinality 1. For ordered a>=b, the opposite-side branch has value a-b and count ma-mb; the same-side branch has value a+b and count ma+mb. Effective counts must retain their sign until tested by absolute value. A zero residual can still carry nonzero effective cardinality or nonempty groups and cannot simply be discarded.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Section 2.3, p. 6, Equation 8; Figure 1 effective counts, p. 5; direct state interpretation
Mechanism #two-phase-complete-branching
The first floor(n/2) branching decisions use disjoint adjacent pairs from the sorted original list, appending each merged residual without reordering the still-unpaired originals. Thereafter the algorithm selects the two largest residuals at each step. Visit difference before sum in both phases. To remain complete, explore same-side alternatives to initial paired differences as well as alternatives in the later phase; irrevocably applying a paired round before starting CKK explores only a restricted set of partitions.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Section 2.3, pp. 6–7 and Figure 2; constructed restricted-first-round comparison
Mechanism #necessary-cardinality-bounds
Let q be the desired absolute subset-cardinality difference, M=sum(abs(mi)) over current residuals, and mmax=max(abs(mi)). Every descendant satisfies max(0,2*mmax-M)<=q<=M, so a target outside that interval permits pruning. The interval is necessary, not sufficient: effective-cardinality magnitudes 2,2,2 allow target 0 through the interval test, but their possible signed absolute totals are only 2 or 6. At the root, a valid target also satisfies 0<=q<=n and has the same parity as n; balanced targets use q=n mod 2.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Section 2.3, p. 6, Equation 9 and Figure 2, p. 7; direct parity and signed-sum counterexample
Mechanism #load-bound-and-incumbent
Maintain an incumbent only from complete partitions satisfying the requested cardinality difference. For residual values with largest value xmax and total S, max(0,2*xmax-S) is a lower bound on final sum difference; a branch cannot improve an incumbent at or below that bound. This unconstrained load bound remains safe under the added cardinality restriction, but an unconstrained completion must not be assumed cardinality-feasible. Exact arithmetic or conservative bounds are needed for certification.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Section 2.2, p. 5; Section 2.3 and Figure 2, pp. 6–7; direct restriction interpretation
Limitation #anytime-and-complete-scope
For balanced targets, the first preferred path gives the BLDM solution; other feasible cardinality targets need not obtain a valid BLDM first result. Full finite search with sound pruning certifies the best valid residue, whereas an interrupted run retains only its feasible incumbent unless it attains a proven lower bound. In a constructed balanced example 8,7,6,5,4, a one-node run retains residue 2 without certification, full search attains 0, and permanently fixed initial pairs cannot improve below 2. The search remains exponential in the worst case.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Sections 2.2–2.3, pp. 4–7; constructed complete, interrupted and restricted searches
Scope #reported-experiments
The source evaluates exact, heuristic and anytime behavior on uniformly sampled finite-precision integers. Its 25-bit experiment averages 100 instances per point, and the high-precision anytime experiment uses 100-item, 150-bit instances with variable improvement across runs. Node counts, arithmetic cost and historical hardware affect the comparisons. Practical claims about twelve-digit inputs are not adopted as universal guarantees, and the statement that finite random inputs have no perfect partitions with probability one is not used as a theorem.
  • supports Source: A complete anytime algorithm for balanced number partitioning · Locator: Section 3, pp. 7–10, Figures 3 and 5; conclusions, p. 11

⚠️ Curated Limitations & Negative Results

  • The source’s named Complete BLDM procedure handles feasible absolute cardinality targets; its fast BLDM first-solution guarantee is limited to balanced targets. Bins are interchangeable and the scope is two-way partitioning.
  • Necessary cardinality bounds do not certify a feasible completion. Signed effective counts, zero-valued residuals and original memberships must remain consistent.
  • The constructed implementation checks 23 valid targets on eight fixed instances, not all possible inputs. Its copying and sorting choices are not assertions about author-code memory or timing.
  • All 12 primary preprint pages were read. Author code, later journal versions and empirical performance were not inspected or replicated.
