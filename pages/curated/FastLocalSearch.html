Fast Local Search

Algorithms AIMech:FastLocalSearch DRAFT
Aliases: FLS
A neighborhood-search procedure that uses activation bits to scan selected subneighborhoods, deactivating unsuccessful ones and reactivating those affected by accepted improvements.
Identity Notes & Concept Scope FLS is the named Voudouris–Tsang neighborhood-reduction procedure, not any fast implementation of local search. It is separable from GLS feature-penalty updates and from the combined Guided Fast Local Search algorithm. Subneighborhoods can overlap; calling them a disjoint partition would overstate the source. Claims & Grounded Evidence

1 Claim
Mechanism #method
Decompose the neighborhood into indexed, possibly overlapping subneighborhoods and supply an activation bit for each. The standalone initialization activates all; the callable routine also permits a supplied subset. Repeatedly scan in the declared order, skipping inactive subneighborhoods. In an active subneighborhood, take the first encountered move that strictly improves the current objective, update the solution, retain that subneighborhood as active, and activate the configured subneighborhoods affected by the move. Continue with the next subneighborhood instead of restarting the entire scan. If no improving move is found after checking the current subneighborhood, deactivate it. Return the current solution when all bits are inactive. In the optional GLS combination, changes to feature penalties reactivate associated subneighborhoods before the next FLS call; the penalty formula itself belongs to GLS.

⚠️ Curated Limitations & Negative Results

  • All bits inactive certifies only the termination of the configured activation scheme. If initial activation or later reactivation omits a region where an improvement exists or becomes possible, the result need not be a local optimum of the full neighborhood. The authors explicitly call the result approximate and warn that improvements can be missed.
  • Activation dependencies, move coverage, order and overlap are problem-dependent. Reactivating every subneighborhood is conservative but can remove the intended computational savings; the method is not a universal speedup guarantee.
  • Within one call the objective is fixed and accepted moves strictly improve it. Curator deduction: finite states and finite move scans imply termination, but neither arbitrary continuous termination nor overall GLS termination follows. Penalty changes between GLS calls alter the objective and require renewed activation.
