ReMixMatch

Algorithms AIMech:ReMixMatch DRAFT
A semi-supervised classifier-training procedure that adjusts weak-view guessed labels toward an estimated class prior, sharpens and anchors those soft targets across strong augmentations, and trains with interpolated pairs plus unmixed consistency and rotation-prediction losses.
Identity Notes & Concept Scope This record follows the paper’s distribution-aligned, augmentation-anchored procedure and explicitly qualifies author-code conventions. It retains the first unmixed strong view for both auxiliary losses and includes the weak view in the mixing pool. It is not an alias for MixMatch, generic distribution matching, hard pseudo-label FixMatch, or the separate CTAugment policy-learning component. Claims & Grounded Evidence

1 Claim
Mechanism #method
For each unlabeled input, compute one weakly augmented current-model probability vector q. Adjust it to Normalize(q*p_prior/p_running), componentwise, using an estimated class prior and a running average of predictions on unlabeled inputs; then sharpen by a positive inverse temperature and normalize again. Hold guessed targets fixed during student differentiation. Construct one strong labeled view and K strong plus one weak view per unlabeled input, assigning its guessed target to all those views. Shuffle the combined labeled/unlabeled pair pool and use the MixMatch-style MixUp routine: a symmetric-Beta coefficient is replaced by max(lambda,1−lambda), and the same coefficient mixes input and target. Train mixed labeled and mixed unlabeled branches with cross-entropy. Also train against the guessed target on the first unmixed strong unlabeled view and apply a four-class rotation-prediction loss on that view, with the paper sampling 0,90,180,270-degree rotations uniformly. Equations3–4 write four weighted sums; the inspected author implementation instead averages each branch before applying its weights, so numerical coefficients must be interpreted with that normalization. The implementation detaches guesses, stabilizes the prior ratio with 1e-6, and uses a rolling prediction buffer. Its CTA entrypoint selects the first weak view as anchor; the standalone no-CTA entrypoint’s default swapped-view configuration is a different option. Parameter EMA is used for evaluation, not as the guessed-label teacher.

⚠️ Curated Limitations & Negative Results

  • The ideal ratio requires defined denominators and a nonzero normalization total; the inspected code adds epsilon. A poorly estimated or mismatched class prior can distort pseudo-targets.
  • Per-example distribution rescaling encourages class-prior alignment but does not impose an exact equality of aggregate predictions and the prior. This follows from the normalization formula and is checked by a finite curator example.
  • The source calls the input-output information objective fair in a class-balance sense; this is not a social-fairness guarantee. Sharpening may reinforce wrong guesses and does not resolve tied maxima into a unique class.
  • The paper and implementation differ in sum-versus-mean loss normalization and rotation sampling: code assigns rotations by batch quarters. No bitwise-equivalent training trajectory or universal hyperparameter values are claimed.
  • CTAugment is an external strong-augmentation component here. Its complete policy-update algorithm, source score convention and variants remain a separate discovery item; no benchmark or source implementation was executed.
