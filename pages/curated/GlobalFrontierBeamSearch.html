Best-first beam search with a global frontier cap

Algorithms AIMech:GlobalFrontierBeamSearch DRAFT
A best-first search procedure that limits the entire open frontier to a fixed number of nodes by discarding the worst-ranked frontier nodes when that capacity is exceeded.
Identity Notes & Concept Scope The qualified name identifies the global frontier truncation described in the 2005 and 2010 search papers. The unqualified phrase best-first beam search is intentionally not an identity alias: Meister, Vieira and Cotterell use that phrase in 2020 for a decoding procedure with a per-sequence-length path limit. A shared name does not equate those pruning rules. No normalized identity match was found across the 442 AIO and 130 prior native records; ignored-inclusive text hits in the main checkout were prior discovery leads, source citations and search-order contrasts, plus incidental lightbulb and wet-bulb dependency substrings, not existing concept records.

Claims & Grounded Evidence

3 Claims
Mechanism #search-procedure
Select the best-ranked node from the current open frontier and add its eligible successors. Whenever the frontier exceeds the chosen capacity, discard its worst-ranked nodes until it fits. Candidates from different depths can therefore compete for the same finite frontier slots.
  • supports Source: A Comparison of Greedy Search Algorithms · Locator: Beam Search, PDF p. 4: best-first versus breadth-first beams
Scope #historical-scope
The beam-stack paper distinguishes its layer-based beam from the broader usage that truncates a best-first open list after adding successors.
  • supports Source: Beam-Stack Search: Integrating Backtracking with Beam Search · Locator: Background: Beam search, PDF p. 1, broader best-first use
Scope #name-disambiguation
The later NLP paper controls how many paths of each sequence length are considered. That per-length counter is a different rule from limiting the total open frontier, so the same phrase does not identify the global-cap procedure without qualification.
  • supports Source: Best-First Beam Search · Locator: Algorithm 2, printed p. 797 / PDF p. 3; Section 3.1 choice point 3 and Table 1, printed p. 798 / PDF p. 4

⚠️ Curated Limitations & Negative Results

  • Global frontier pruning can permanently remove a needed path; the cap alone establishes neither completeness nor optimality.
  • The cap applies to the open frontier, not automatically to closed tables, predecessor storage, generated successors or the total program memory.
  • No equivalence to breadth-first beam output, monotonic quality with larger width, or universal runtime advantage is asserted.
