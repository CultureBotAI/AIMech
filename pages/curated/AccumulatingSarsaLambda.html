Accumulating Sarsa(lambda)

Algorithms AIMech:AccumulatingSarsaLambda DRAFT

An episodic tabular on-policy control algorithm that propagates each selected-next-action temporal-difference error through accumulating state-action eligibility traces, retaining learned action values and resetting traces between episodes.

Mechanism #tabular-on-policy-control
The selected episodic tabular Sarsa(lambda) procedure learns an action-value table Q(s,a) and derives an exploratory behavior policy from its current values, for example an epsilon-greedy policy. It assigns credit using an accumulating eligibility trace for each state-action pair rather than only the current pair.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Sarsa(lambda), HTML · Locator: Section 7.5, introduction and on-policy discussion preceding Figure 7.11.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Section 7.5, Figure 7.11, linked pseudotmp12.png: table initialization, selected actions and state-action trace loop.
Mechanism #selected-next-action-error
After executing A_t in S_t and observing R_(t+1) and a nonterminal S_(t+1), select A_(t+1) from the policy derived from the pre-update table Q_t. Form delta_t=R_(t+1)+gamma*Q_t(S_(t+1),A_(t+1))-Q_t(S_t,A_t), then carry that already selected action into the next transition. The bootstrap uses the selected action value, not a maximum over actions or an expected action value.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, selected-action TD-error image · Locator: Section 7.5, unnumbered TD-error display immediately before Equation 7.13, linked imgtmp57.png.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Figure 7.11, linked pseudotmp12.png: choose a-prime before computing delta and updating Q; assign a <- a-prime after the trace loop.
Mechanism #accumulating-trace-credit
Let E_t be the trace used in the value update at time t, with E_(-1)=0 at an episode start. For every tabulated pair, E_t(s,a)=gamma*lambda*E_(t-1)(s,a)+1{(s,a)=(S_t,A_t)} and Q_(t+1)(s,a)=Q_t(s,a)+alpha*delta_t*E_t(s,a). The Q values used to compute delta_t are pre-update values. Figure 7.11 implements this recurrence by incrementing the stored current-pair trace, updating Q using the resulting traces, and then decaying the stored traces by gamma*lambda; that decay is not applied again before the next increment.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Equation 7.13 image · Locator: Section 7.5, Equation 7.13, linked numeqtmp40.png: current-pair increment and decay for all other pairs.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, action-value update image · Locator: Section 7.5, unnumbered action-value update preceding the TD-error display, linked imgtmp56.png.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Section 7.5, Figure 7.11, linked pseudotmp12.png: increment, value update, then stored-trace decay; episode initialization is corrected by the separately cited author errata.
  • supports Source: Reinforcement Learning: An Introduction — Official first-edition errata · Locator: Entry for boxed algorithms on pp. 174, 181, 184, 200, 212 and 213: move eligibility zeroing inside the episode loop.
Mechanism #episodic-terminal-and-reset
Initialize Q before learning and retain its learned entries between episodes. Reset all eligibility traces to zero at each episode start, following the author errata. At a terminal successor, use zero continuation value, so the final error is R_(t+1)-Q_t(S_t,A_t); apply that reward update to all eligible pairs before starting the next episode. No further environment action is executed from the terminal state.
  • supports Source: Reinforcement Learning: An Introduction — Section 6.4, Sarsa: On-Policy TD Control, HTML · Locator: Section 6.4, paragraph immediately after Equation 6.5: the successor action value is defined as zero at a terminal state. The linked terminal symbols are retained separately from the HTML bytes.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Section 7.5, Figure 7.11, linked pseudotmp12.png: Q initialization, episode loop, value updates and terminal stopping test.
  • supports Source: Reinforcement Learning: An Introduction — Official first-edition errata · Locator: Entry for boxed algorithms on pp. 174, 181, 184, 200, 212 and 213: eligibility traces are zeroed inside each episode loop, not only before the first episode.
Scope #trace-memory-and-one-step-limit
From zero episode traces, a pair receives the discounted sum of its visit indicators: E_t(s,a)=sum_(k=0..t)(gamma*lambda)^(t-k)*1{(S_k,A_k)=(s,a)}. Repeated visits therefore accumulate credit rather than resetting the chosen trace to one. At lambda=0, only the current pair receives credit, giving one-step tabular Sarsa under the same action timing and terminal convention. Selecting an exploratory action does not by itself cut the traces in this accumulating rule.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Equation 7.13 image · Locator: Section 7.5, Equation 7.13, linked numeqtmp40.png. The finite-sum expansion and lambda-zero specialization are direct algebraic consequences of this recurrence with zero episode initialization.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Figure 7.11, linked pseudotmp12.png: exploratory policy selection and unconditional trace update; no action-greediness trace-cut branch.
Scope #table-update-and-sparse-boundary
The literal tabular algorithm visits every state-action entry to update its value and trace at each transition. An implementation can omit operations on exactly zero trace entries without changing these updates. Discarding small but nonzero traces is an approximation; neither the recurrence nor sparse storage guarantees a fixed small number of active pairs.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.5, Figure 7.11 image · Locator: Section 7.5, Figure 7.11, linked pseudotmp12.png: the explicit for-all-state-action-pairs loop.
  • supports Source: Reinforcement Learning: An Introduction — Section 7.9, Implementation Issues, HTML · Locator: Section 7.9, Implementation Issues, first two paragraphs and Exercise 7.9: full-table expense, tracking nonzero traces and a positive trace threshold. Exact-zero versus nonzero truncation is an algebraic qualification of that discussion.

⚠️ Curated Limitations & Negative Results

  • This identity is the corrected episodic tabular accumulating Sarsa(lambda) procedure. It does not denote the whole Sarsa family, original neural MCQ-L, an isolated eligibility component, replacing-trace control or true online Sarsa. Shared selected-action errors, one-hot representations and endpoint coincidences do not establish exact whole-method aliases or disjointness.
  • The acquired Figure 7.11 places trace zeroing before the episode loop. The separately acquired official first-edition errata moves it inside that loop, and the selected scope incorporates that explicit correction. The original image is retained; this observation does not establish a defect in uninspected author software.
  • In the neighboring Section 7.8, the prose resets the selected replacing trace to one, while its acquired Equation 7.17 image prints one plus the decayed old trace for that pair. This local image/prose conflict is not used to redefine Equation 7.13 or the selected accumulating algorithm. The separately linked function-approximation correction is context, not its defining procedure.
  • Finite-step online accumulating updates do not generally equal an offline lambda-return update that freezes the values used in all returns, including at lambda=1. Exact online forward-view guarantees of true-online methods cannot be transferred to this procedure. With gamma=lambda=1, repeated visits can make traces grow and continuing returns need not be finite.
  • For 0<=gamma*lambda<1 and zero initial traces, the visit-sum representation bounds each trace by 1/(1-gamma*lambda), but it does not bound Q or establish stable control or convergence. Exploration, coverage, step sizes, reward and episode assumptions still matter. No universal convergence, optimality or performance superiority follows, and the book's historically unpublished convergence discussion is not a current-theory conclusion.
  • The selected procedure is tabular. Neural or general nonlinear approximation, off-policy corrections, arbitrary replacement of the trace, variable-parameter conventions and function-approximation variants require separate method assessment. The original neural MCQ-L account remains a historically related realization whose operation ordering and boundary conditions are not identified with this record.
  • The defining evidence is the author-hosted 1998 first-edition HTML, separately retained equation and algorithm image bytes, and official errata. Each artifact checksum covers only that file; an HTML checksum does not cover externally linked images. The 2005 conversion footer is not the publication year. The acquired September 2016 book draft lacks a Sarsa(lambda) section in its contents, and JMLR 2016 pp. 14–15 serve only as contextual comparison. No complete-book reading, code execution, benchmark reproduction or complete-proof certification is asserted.
