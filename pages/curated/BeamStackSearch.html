Beam-stack search

Algorithms AIMech:BeamStackSearch DRAFT
A layer-based beam search augmented with a stack of admitted evaluation ranges so that backtracking systematically revisits successors previously discarded by beam-width pruning.
Identity Notes & Concept Scope Beam-stack search combines breadth-first beam expansion with chronological backtracking and an incumbent solution-cost bound. It is distinct from permanent beam pruning, limited-discrepancy beam backtracking, and the separately named iterative-deepening BSIDA-star variant. Mechanism #search-procedure
Use an admissible cost estimate f=g+h and an incumbent upper bound U. For each expanded layer, store a range of successor evaluations admitted to the next beam. Width pruning records the smallest rejected evaluation as the upper endpoint. On backtracking, advance the deepest unfinished range and regenerate that layer’s successors. Improved solutions lower U; exhaustion of the stack ends the improvement search.

Limitation #bound-and-incumbent-scope
The basic method starts from a bound corresponding to an actual solution, while the paper introduces a separate iterative-deepening version when such a bound is unavailable. As an implementation obligation inferred from the displayed initialization and return logic, a wrapper must preserve the initial incumbent when the improvement search finds no better path.

⚠️ Curated Limitations & Negative Results

  • The paper’s termination and optimality argument assumes finite branching, a positive lower bound on operator cost and a finite initial upper bound supplied by an actual solution, together with admissible pruning. It is not a guarantee for arbitrary zero-cost cycles, an infinite bound or arbitrary duplicate policies.
  • Ties require a consistent ordering, or enough beam capacity to retain the unbroken tie group; a bare numeric range with unresolved ties is insufficient.
  • The baseline retains up to a beam of nodes per depth layer plus the beam stack. O(w*d) node storage does not mean a fixed total-memory cap independent of search depth.
  • The initially supplied solution must remain available if no improvement is found. An upper-bound number alone is not a returned path; this record does not certify the displayed pseudocode as a complete implementation.
