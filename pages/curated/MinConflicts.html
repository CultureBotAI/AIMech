Min-conflicts heuristic

Algorithms AIMech:MinConflicts DRAFT
Aliases: Min-conflicts
A constraint-repair value-selection heuristic that uses a complete assignment to choose a value for a conflicted variable with as few conflicts as possible, breaking tied minimum choices randomly in the inspected formulation.

Claims & Grounded Evidence

1 Claim
Mechanism #method
For the stated binary-CSP formulation, maintain one domain value for each variable. Select a variable currently in conflict with at least one other variable, and evaluate its possible values against the other current assignments. Choose a minimum-conflict value, breaking ties randomly. The source footnote interprets the binary score as the number of conflicting other variables; for general constraints, estimating how many variables need repair depends on the constraint. The current value remains an eligible candidate, so an update can leave the assignment unchanged or move sideways. Initialization and the choice among conflicted variables belong to the surrounding search strategy. In the described local-repair use, repeat repairs until a consistent assignment is found or a chosen budget ends. The same value-ordering idea can instead guide an informed backtracking procedure; that procedure is not an exact synonym for the heuristic.

⚠️ Curated Limitations & Negative Results

  • Minimizing local conflicts does not necessarily reduce distance to a satisfying assignment. Ties, unchanged assignments and non-solution local optima can prevent a local-repair search from terminating successfully.
  • Completeness depends on the outer search strategy. The source contrasts a potentially stuck hill-climbing implementation with a complete backtracking strategy; neither a guarantee of eventual success nor a proof of unsatisfiability follows from the value heuristic alone.
  • General-constraint scoring requires a declared repair interpretation. Counting violated constraints, distinct conflicting variables, weighted violations or individual forbidden tuples can produce different rankings and should not be silently interchanged.
  • Initialization, variable ordering, ties and budgets affect behavior. The source’s simplified probability analysis makes additional problem assumptions and is not asserted as a universal performance guarantee. No numerical benchmark claim is curated.
