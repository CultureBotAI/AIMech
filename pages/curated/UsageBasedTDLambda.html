Usage-based TD(lambda)

Algorithms AIMech:UsageBasedTDLambda DRAFT
An on-policy linear state-value prediction algorithm that combines ordinary accumulating TD eligibility traces with componentwise step sizes equal to reciprocals of a recency-adjusted feature-usage vector.
Identity Notes & Concept Scope The selected source-defined linear on-policy prediction algorithm applies newly computed inverse feature-usage step sizes outside an ordinary accumulating TD trace. It differs from usage-based true online TD, whose Dutch trace contains the step vector and whose update corrects changing predictions, and from the broader temporal-difference family and off-policy WIS hosts. Mechanism #on-policy-accumulating-prediction
Usage-based TD(lambda), called U-TD(lambda) in the source, evaluates state values from on-policy reward transitions with a fixed linear representation V_t(s)=theta_t^T*phi(s). It combines the specified feature-usage step schedule with the ordinary accumulating TD(lambda) host; it is not a control or action-selection procedure.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Section 6, author PDF p. 7, named on-policy extensions; Appendix A.7, p. 18, Algorithm 4; linear policy-evaluation setting in Section 3, pp. 3–4.
Mechanism #on-policy-feature-usage-step
With ⊙ denoting componentwise multiplication, update u_(t+1)=(1-eta*(phi_t⊙phi_t))⊙u_t+phi_t⊙phi_t, then set alpha_(t+1) to the componentwise reciprocal of new u_(t+1). A reciprocal at zero is defined as zero by the source. Algorithm 4 initializes u_0=u_init*1 and e_(-1)=0, with chosen theta_0, u_init>=0 and eta>=0.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Section 2, author PDF p. 3, Equations 5–6 and componentwise division convention; Appendix A.7, p. 18, Algorithm 4, initialization and usage lines.
Mechanism #ordinary-eligibility-and-current-error
The accumulating trace is e_t=gamma_t*lambda_t*e_(t-1)+phi_t. Compute delta_t=R_(t+1)+gamma_(t+1)*theta_t^T*phi_(t+1)-theta_t^T*phi_t using pre-update theta_t. Current gamma_t*lambda_t governs trace carry-over, while gamma_(t+1) discounts the next-state value in the target. The step-size vector is not part of this ordinary trace recurrence.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Appendix A.7, author PDF p. 18, Algorithm 4, eligibility and TD-error lines; state-dependent discount and lambda setting in Sections 3 and 5, pp. 3–5.
Mechanism #component-scaled-main-increment
After computing new alpha_(t+1), new e_t and delta_t, update theta_(t+1)=theta_t+alpha_(t+1)⊙(delta_t*e_t). Algorithm 4 requires the usage, eligibility and value-weight vectors but no importance ratio, secondary usage vector v, auxiliary GTD weights w, provisional weights d or stored previous-weight prediction.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Appendix A.7, author PDF p. 18, complete Algorithm 4; Section 6, p. 7, combination with the ordinary on-policy TD host.
Scope #one-step-and-qualified-gtd-specializations
When gamma_t*lambda_t=0, the eligibility is phi_t and the update is the one-step usage-scaled TD increment alpha_(t+1)⊙(delta_t*phi_t). With matching states and initialization, Algorithm 4 is also obtained from WIS-GTD(lambda) by setting all rho to one, beta=0 and w_0=0. Those conditions remove the off-policy usage correction and keep the auxiliary correction zero.
  • supports Source: Off-policy learning based on weighted importance sampling with linear computational complexity · Locator: Appendix A.7, author PDF p. 18, Algorithms 2 and 4; Section 6, p. 7, on-policy relationship paragraph. Zero-decay and zero-w qualifications follow directly from the recurrences.
Scope #linear-bookkeeping-and-usage-scope
The printed U-TD(lambda) update uses a fixed number of length-n vectors and O(n) dense arithmetic and storage per transition for n features. Its feature-usage recurrence is shared with U-SGD, but the host update uses a temporal-difference target and an accumulating trace. The sample-average identity stated for U-SGD in Theorem 1 is not thereby a theorem for arbitrary online U-TD histories.

⚠️ Curated Limitations & Negative Results

  • This identity is the named 2015 usage schedule combined with the ordinary accumulating TD host. It is not the unrestricted TD(lambda) family, U-SGD, usage-based true online TD, accumulating Sarsa control, an isolated trace or off-policy WIS-GTD. Shared steps and parameter specializations do not establish complete-method aliases.
  • The source explicitly leaves convergence analysis of its new algorithms for future work. The usage schedule and a linear representation do not guarantee bounded weights, monotonic error reduction, convergence or universal performance. The reported on-policy experiments are bounded prediction tasks with specified representations and parameter searches.
  • The printed eta>=0 range alone does not ensure positive usage for arbitrary feature magnitudes. For scalar phi=1 and u_init=0, eta=3 gives usage 1 then -1, and eta=2 gives zero on the second update. The reciprocal-zero convention is defined but is not a positivity or stability proof; feature scale and initialization matter.
  • Theorem 1 is an algebraic statement about U-SGD for the observed target sequence under tabular representation, zero initial usage and weights, and 0<=eta<1. It does not require invented independence or exogeneity assumptions. Its update is not the arbitrary bootstrapped accumulating TD host here; lambda=1 or inverse usage alone does not establish a sample-average or Monte Carlo identity. A finite repeated-feature example separates U-TD from usage-based true online TD even at lambda=1.
  • The componentwise reciprocal is computed after updating usage, and it scales the new accumulating trace in the main increment. Moving it into a Dutch trace, using old usage, changing the target to a prior-weight prediction or adding an auxiliary correction changes the procedure. Variable feature or parameter conventions require explicit reassessment.
  • The selected method is on-policy linear state-value prediction. It does not implement importance-sampling correction, nonlinear representation learning, action-value Sarsa control or policy improvement. Dense O(n) bookkeeping does not mean cost only in current nonzero features, nor does it include feature construction or environment interaction.
  • The defining evidence is the acquired eighteen-page author combined paper and Appendix A, with native-text correspondence to the retained official main paper and supplement. Its embedded 2016 creation date is not a scientific revision date. Algorithm 4 is separately identifiable from the unresolved WIS-TO-GTD Algorithm 3. No complete proof, source-code correctness or benchmark reproduction is certified by this evidence scope.
