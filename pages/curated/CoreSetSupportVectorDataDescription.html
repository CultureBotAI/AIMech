Core-set support vector data description

Algorithms AIMech:CoreSetSupportVectorDataDescription DRAFT
Aliases: CSVDD
An approximate one-class training algorithm that grows a core subset using the nearest expanded-sphere violator, refits support vector data description and enforces radius growth until the expanded sphere meets an outlier-count stopping rule.
Identity Notes & Concept Scope This record denotes the Chu-Tsang-Kwok2004 CSVDD training procedure. It is distinct from ordinary SVDD, squared-slack SVDD, sphere-based clustering and hard-MEB core-vector solvers. Later CVDD usage is not assumed to be an exact alias. Claims & Grounded Evidence

7 Claims
Mechanism #underlying-soft-sphere-problem
The underlying target-only SVDD minimizes R²+(1/(nu*N))*sum_i xi_i with R>=0, xi_i>=0 and ||phi(x_i)-c||²<=R²+xi_i, for0<nu<1. Its displayed dual maximizes sum_i alpha_i*K_ii-alpha^T*K*alpha with sum(alpha)=1 and0<=alpha_i<=1/(nu*N). Thus the slack penalty is linear, not the squared-slack formulation used by L2-loss SVDD or a hard-MEB reformulation. Positive-semidefinite kernels permit feature-space distances without explicitly constructing features. Radius recovery from a free boundary coefficient requires such a coefficient to exist.
  • supports Source: Scaling up Support Vector Data Description by Using Core-Sets · Locator: Section II, PDF p2, primal and dual displays, center recovery and kernelization paragraph
Mechanism #core-initialization
Fit ordinary SVDD to a fixed-size random sample of n0 observations and select the sampled observation z closest to that fitted center as a probable inlier. Choose a random sampled x, find its farthest observation y in the full dataset, and set D=||phi(x)-phi(y)|| and initial radius R1=D/k for k>1. Start the core with z and center c1=phi(z). This initial center is an observation, not the fitted sample center; the initial radius need not equal the one-point minimum-enclosing-ball radius. The probable-inlier choice is a heuristic, not a guarantee that z is normal.
  • supports Source: Scaling up Support Vector Data Description by Using Core-Sets · Locator: Section III-A, PDF pp2-3, Equation1
Mechanism #nearest-violator-and-radius-growth
At iteration i, compute P_i={x in the full dataset:||phi(x)-c_i||>(1+epsilon)*R_i}. Stop when |P_i|<nu*N, with a strict inequality. Otherwise select the observation in P_i outside the current core that is nearest to c_i, enlarge the core, refit SVDD on that subset, and enforce R_(i+1)>=(1+delta*epsilon)*R_i for positive delta and epsilon. Repeat with the new center and radius. Nearest violating-point selection, soft subset refits and imposed radius growth distinguish this procedure from farthest-point hard-MEB core algorithms.

Limitation #expanded-quota-and-objective-boundary
Termination checks the expanded radius (1+epsilon)*R, not the unexpanded sphere used by ordinary SVDD prediction. A permitted exact initialization illustrates the difference: use linear-kernel points0,1/10,1, nu=epsilon=1/5, n0=3, random x=0 and k=5/4. The initial sample SVDD has center1/2 and radius1/2; z=1/10 is its unique nearest observation. D=1 yields R1=4/5 and expanded radius24/25. No training point lies outside the expanded sphere, so the procedure stops immediately; one of three lies outside the original sphere, exceeding nu=1/5. The stopped sphere has full SVDD objective277/300 versus optimum1/4, a ratio277/75 greater than(1+epsilon)². This is exact curator arithmetic for allowed procedure choices, not a historical benchmark or claim about the paper’s experimental settings.

Limitation #conditional-cost-analysis
The source derives O(M²*N+M⁴) work for M core additions using unit-cost kernel evaluations and a cubic subset-QP cost, and states M<=k/(delta*epsilon). Its O(N/epsilon²+epsilon^-4) form treats k and delta as fixed. The experiments instead set delta=0.01*epsilon; substitution into the same cost model gives O(N/epsilon^4+epsilon^-8) at fixed k. These expressions omit dimension-dependent kernel cost and input storage. The stated iteration argument uses the optimal full-data MEB radius as an enclosure bound, but an arbitrary current convex-hull center can require up to twice that radius: points0,2 have optimal radius1 at center1 and farthest distance2 from center0. The literal constant bound therefore needs its center assumptions checked; it is not a proof of soft-SVDD objective or decision-boundary approximation.
  • supports Source: Scaling up Support Vector Data Description by Using Core-Sets · Locator: Section III-C, PDF p3, Equation3; Section IV introduction, PDF pp3-4, parameter choices; curator dependence and center calculations in research/discovery/core-set-svdd-boundaries.py
Limitation #subproblem-and-implementation-conventions
A reimplementation must specify the subset SVDD penalty convention, radius-growth enforcement, numerical tolerances and tie or missing-free-support handling. Merely retaining the full-data cap1/(nu*N) on a smaller equality-simplex subproblem can make it infeasible: for N=100, nu=1/10 and a two-point core, the sum of upper bounds is1/5<1. Using the subset sample size gives a different cap. The paper says to run SVDD on the subset but does not expose a complete CSVDD implementation resolving all such choices. This feasibility calculation is not evidence that its historical code used the full-data cap.

Scope #empirical-and-identity-scope
Section IV explicitly names the method Core-set Support Vector Data Description, CSVDD. The two application studies concern BioID-derived face detection and MNIST one-class digit detection, with selected Gaussian kernels, nu values, tolerances,20 random repetitions and historical MATLAB/MOSEK3, dd_tools and LIBSVM configurations. The reported time, memory failures and AUC trade-offs are specific to those data and implementations. They do not prove universal accuracy, speed or soft-objective approximation. This record does not equate CSVDD with every later method called core vector data description or CVDD.

⚠️ Curated Limitations & Negative Results

  • The stopping quota applies the expanded sphere. Neither a full-data soft-SVDD objective approximation nor a prediction/generalization guarantee follows from it.
  • Source complexity depends on parameter choices, kernel cost, subset solves and radius/center assumptions. Input storage is separate.
  • All six primary PDF pages were visually read. Exact rational calculations test stated formulas and an allowed initialization; no historical implementation, optimizer or benchmark was executed.
  • CSVDD remains a native DRAFT. Later CVDD variants, the related MPhil thesis, RAPID, minimax/LP novelty methods and later regularized or accelerated support descriptions remain unresolved.
