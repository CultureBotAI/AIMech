Neural GPU

Architectures AIMech:NeuralGPU DRAFT
Aliases: Neural GPUs
A recurrent neural architecture that embeds a complete symbolic sequence in a spatial state grid and repeatedly applies shared convolutional gated updates before reading an output sequence from the final grid.

The named Neural GPU evolves a complete input grid with time-shared convolutional gated updates. It is not GPU hardware, an NTM external read/write controller, generic GRU, DMN episodic QA or typed-graph GG-NN. Follow-up size/curriculum changes are scoped observations about the architecture rather than separate trained-model records.

Claims & Grounded Evidence

6 Claims
Mechanism #initial-grid-and-tied-evolution
Embed the complete input sequence into the first column of a width-by-length grid of feature vectors and initialize the remaining grid positions to zero. Apply a fixed stack of convolutional gated recurrent units repeatedly for a number of time steps tied to input length, sharing each stack position’s parameters across time. The original construction supplies no new external input at each step. A learned output projection reads the first column of the final grid; symbol argmax is an inference operation, while training uses softmax negative log probability.
  • supports Source: Neural GPUs Learn Algorithms · Locator: Section 2, PDF pp. 3–4, CGRU and state-update equations, Figure 1 and output/loss description
Scope #gate-and-spatial-boundaries
The displayed CGRU update weights the old state by u and the candidate by 1-u. Its candidate convolves the reset-multiplied state, U*(r*s), which is generally different from applying a spatially varying reset after convolution. The method specifies same-size stride-one convolutions with zero padding; local shared kernels do not imply invariance to arbitrary grid permutations or exact translation equivariance across finite boundaries. Printed mixed index conventions are a mathematical description rather than executable array indexing.
  • supports Source: Neural GPUs Learn Algorithms · Locator: Section 2, PDF p. 3, GRU/CGRU, convolution and initialization definitions; constructed gate, reset and finite-boundary examples
Scope #relaxation-and-training-protocol
The original training uses a length curriculum, hidden-state dropout and parameter-sharing relaxation. Relaxation begins with multiple initially identical parameter sets used cyclically across steps, penalizes differences from their mean, increases the pull toward sharing as the curriculum advances, then averages the sets and continues training with one shared set. This is temporary training-time untying, not an output ensemble or a permanent growth of inference parameters with sequence length. The selected optimizer, hyperparameters and random restarts are part of the reported protocol rather than a guarantee of successful learning.
  • supports Source: Neural GPUs Learn Algorithms · Locator: Section 2, PDF p. 4; Section 3.3, including 3.3.1–3.3.2, pp. 6–7; constructed parameter-average versus output-average example
Limitation #parallel-depth-and-total-work
For fixed grid width, feature width, kernel sizes and stack depth, increasing input length increases both grid size and the number of recurrent steps while leaving tied inference parameters fixed. Linear sequential depth in input length therefore coexists with quadratic total local-update work in this specified unrolling. The cellular-automaton analogy and representational universality discussion do not prove that training finds a correct algorithm or establish measured hardware speed for arbitrary configurations.
  • supports Source: Neural GPUs Learn Algorithms · Locator: Section 2, PDF pp. 3–4; Section 4, p. 8
  • supports Source: Extensions and Limitations of the Neural GPU · Locator: Section 3 and Figure 1, PDF pp. 3–4; fixed-width arithmetic counts
Limitation #original-finite-generalization-evidence
The original binary arithmetic tasks concatenate lower-endian operands with an operator symbol rather than aligning their digits. Selected runs trained on operands up to twenty bits are evaluated on substantially longer inputs, including two-thousand-bit operands; an answer counts as correct only when the complete output is correct. The experiments also include sequence transformations, and successful long generalization is sensitive to hyperparameters and random initialization. The paper reports failure to learn decimal multiplication in its original setting. These finite tests and selected successful runs do not certify every input or every trained model.
  • supports Source: Neural GPUs Learn Algorithms · Locator: Sections 1.1–2, PDF pp. 2–3; Sections 3–4 and Table 1, pp. 4–8
Limitation #followup-structured-input-failures
A follow-up study changes model size and curriculum, enabling decimal arithmetic in selected settings, but finds that high accuracy on long random inputs can coexist with failures on long carry chains, highly structured numbers and leading-zero-padded single-digit products. Training on some hard examples improves the observed range without establishing unlimited carry generalization. These results concern the follow-up configurations and tested instances, not a claim that every original model fails identically. They directly limit an all-input interpretation of successful length extrapolation.
  • supports Source: Extensions and Limitations of the Neural GPU · Locator: Sections 4–5, PDF pp. 4–8, Figures 2–6 and Tables 2–3; Conclusion, p. 9

⚠️ Curated Limitations & Negative Results

  • The named Neural GPU is an architecture, not GPU hardware, a particular trained checkpoint, a Neural Turing Machine or a guarantee of algorithmic correctness.
  • Full nine-page original arXiv1511.08228v3 and eleven-page follow-up arXiv1611.00736v2 PDFs were read. Different source configurations and access versions remain explicit.
  • Author implementations, other versions and model training were not inspected or run. Chosen calculations establish algebraic distinctions only, not empirical replication.
  • Later curriculum successes qualify the original decimal-multiplication failure; structured-input counterexamples qualify generalization language. DRAFT remains.
