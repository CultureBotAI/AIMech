HAT (Hardware-Aware Transformers for Efficient Natural Language Processing)

Architectures AIMech:HATHardwareAwareTransformersForEfficientNLP DRAFT
Aliases: HAT, Hardware-Aware Transformers, HAT SuperTransformer with Arbitrary Encoder-Decoder Attention
HAT (Hardware-Aware Transformers) is a hardware-aware Neural Architecture Search (NAS) framework for sequence-to-sequence encoder-decoder Transformers that breaks the information bottleneck between encoder and decoder via Arbitrary Encoder-Decoder Attention (allowing each decoder layer to attend to the concatenated key-value representations of the last 1, 2, or 3 encoder layers with zero extra parameters), enables layer-wise Heterogeneous Transformer Layers (varying embedding dimensions, FFN hidden dimensions, attention head counts, and decoder layer count across ~10^15 candidate SubTransformers), trains a single weight-sharing SuperTransformer by uniformly sampling SubTransformers and slicing front-prefix weight subtensors, and executes evolutionary search guided by a target-device MLP Latency Predictor to extract specialized SubTransformers meeting strict hardware latency constraints.
Identity Notes & Concept Scope Distinct from Evolved Transformer (So et al., 2019), which searches homogeneous cell structures without hardware latency feedback at >10,000x higher GPU cost, distinct from Once-for-All (Cai et al., 2020), which targets convolutional neural networks via progressive shrinking rather than encoder-decoder Transformers with arbitrary cross-attention spans, and distinct from DynaBERT (AIMech:DynaBERTDynamicBERTWithAdaptiveWidthAndDepth), which adapts encoder-only BERT width and depth via importance-ordered head/neuron rewiring and distillation.

Mechanism #hat-arbitrary-encoder-decoder-attention-and-heterogeneous-layers
HAT defines a heterogeneous design space of ~10^15 encoder-decoder SubTransformers in which each layer independently selects its FFN inner dimension and attention head count while Arbitrary Encoder-Decoder Attention lets each decoder layer attend to the last 1, 2, or 3 encoder layers by concatenating their key and value vectors along the sequence dimension without adding trainable parameters.

  • supports Source: HAT: Hardware-Aware Transformers for Efficient Natural Language Processing · Locator: design_space_cardinality and arbitrary_enc_dec_attention
Mechanism #hat-weight-sharing-supertransformer-and-latency-predictor-search
HAT trains a single weight-sharing SuperTransformer by uniformly sampling SubTransformers at each step and updating their front-slice weight subtensors, and pairs the SuperTransformer with a 3-layer MLP hardware latency predictor (trained on 2000 measured architecture-latency pairs with ~0.1 ms/0.1 s RMSE) during evolutionary search under a hard hardware latency budget.
  • supports Source: HAT: Hardware-Aware Transformers for Efficient Natural Language Processing · Locator: Section 3.2 (Performance Approximation) and Section 3.3 (Hardware Latency Constraint), Figures 7-8, pp. 7679-7680
  • supports Source: HAT: Hardware-Aware Transformers for Efficient Natural Language Processing · Locator: extract_front_subtensor and main
Application #hat-hardware-specialized-machine-translation-speedup
On WMT'14 En-De, WMT'14 En-Fr, WMT'19 En-De, and IWSLT'14 De-En across Raspberry Pi-4 ARM CPU, Intel Xeon CPU, and Nvidia Titan Xp GPU, HAT achieves up to 3x latency speedup and 3.7x smaller model size over Transformer-Big while cutting NAS search cost by 12,041x compared to Evolved Transformer, automatically discovering deep-and-thin models for ARM CPU versus shallow-and-wide models for GPU.
  • supports Source: HAT: Hardware-Aware Transformers for Efficient Natural Language Processing · Locator: Section 4.2 (Main Results), Table 2, Table 3, and Figure 12, pp. 7681-7684
Limitation #hat-post-search-retraining-and-device-profiling-limitation
Although the SuperTransformer ranks candidate SubTransformers accurately, achieving peak final translation BLEU requires retraining the discovered SubTransformer from scratch for 40K steps, and each new target hardware platform requires profiling ~2000 architectures to fit a device-specific latency predictor.
  • supports Source: HAT: Hardware-Aware Transformers for Efficient Natural Language Processing · Locator: Section 3.3 (Latency Predictor) and Section 4.1 (Search Cost / Retraining), pp. 7680-7681

⚠️ Curated Limitations & Negative Results

  • Extracted SubTransformers require post-search retraining from scratch (e.g., 40K steps) to reach full stand-alone BLEU accuracy.
  • Deploying to a new hardware target requires collecting ~2000 on-device latency measurements to train the device-specific MLP latency predictor.
